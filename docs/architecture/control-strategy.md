# 控制策略说明

版本：v2.0，2026-09-18。对应根活动项`PLC-EDGE-SINGLE-CONTROL-20260918`。替代v1.7多入口方案（旧正文见Git历史`a829ab7`）；2026-09-19追加同地址Modbus TCP代理实现，默认关闭，现场写控未开放。

## 1. 唯一上位控制入口

专用PLC屏与HMI2将启停/调频请求交现场Edge；HMI2浏览器仍只访问同源hmi-runtime。Edge统一裁决上位来源权限、人工/自动和冲突；DAQ保留可信命令执行边界。hmi-runtime负责客户端请求、状态与本地在途协调，不成为独立于Edge的PLC控制权拥有者。

PLC不再仲裁屏幕/算法的owner、direct授权或来源缓冲，但保留实际输出、顺控、限幅、联锁、本地/检修限制、急停/保护、命令有效性和失联处置。必须关闭旧屏生产直写路径并验证其他上位来源不能绕过。两屏按最近有效人工操作受理来源切换，所有请求仍经Edge授权与单一执行入口，不能让多个物理写通道任意覆盖。

现役代码authority/epoch和质量门禁本轮不删；替代接口通过审查、回归和现场验收前继续拒绝未签收写入，不以常量owner或伪造ACK绕过。

## 2. 第一版功能与点位

唯一清单见 [I/O控制契约](../plc/io-and-control-contract.md)：19项设备/用途、21个原始M候选；4个启动参数D3000/D3002/D3004/D3008。D3002已由人类订正；D3006/D3007、备用和独立方向/星角UI项退出本轮输入。绞龙1/2方向地址未选定。

第一版可先做人工操作，自动调节另验。当前仅M1001常驻只读诊断有验收证据，控制候选没有生产写验收；17个保留M已有隔离置1→M/Y读回，但停止、顺控、保护和真实运转未验。

启动频率参数与运行中目标分别建模。D30–D35/AO不能当已允许直写SP或VFD实际反馈。D3006/D3007弃用不自动减少运行调频通道数；最终通道、写地址和单位范围按现场核定，不因旧六SP界面存在就宣称可控。

## 3. 两块屏与Edge自动控制的控制权

2026-09-19人类最新决定：**哪块屏实际操作，哪块屏获得人工控制权；专用屏与HMI2同级，不要求原屏先移交。** 取代同轮较早“当前操作者优先、必须移交”的答复。本节是整理后的目标行为，当前实现差距见§6，不能视为双屏/自动写已上线。

### 3.1 控制来源、模式与可写状态分开

三种业务来源是专用屏`192.0.2.100`、HMI2（经hmi-runtime）和Edge自动算法。PLC本地/检修、急停、联锁与设备保护属于最终限制，不作为第四个上位来源。保护优先于所有业务来源，任一屏不能通过接管解除保护。

本期按同一工艺线统一仲裁，不拆成“专用屏控制一台、HMI2控制另一台、算法控制第三台”的并行模式。一处有效人工启停/调频即退出该线AUTO。后续若需要按设备独立自动，须单独决定，不在本轮暗中引入。

| 业务状态 | 当前来源 | 谁能发下一条普通控制命令 | 其余来源 |
|---|---|---|---|
| 手动待操作 | 无 | 任一授权屏的有效人工操作可取得控制权 | 算法只分析，不写入 |
| 专用屏手动 | 专用屏 | 专用屏可继续操作；HMI2新的有效人工操作可切走控制权 | 算法不写入；两屏均可读取 |
| HMI2手动 | HMI2 | HMI2可继续操作；专用屏新的有效人工操作可切走控制权 | 算法不写入；两屏均可读取 |
| 自动 | Edge算法 | 已授权算法；任一屏有效人工操作可中断自动并接管 | 两屏可读取和发起人工操作 |
| 自动暂停 | 无自动写权限 | 条件恢复后明确重新启用AUTO，或由任一屏有效人工操作进入MANUAL | 自动不得自行恢复 |
| 控制受阻 | 无可用写入口 | 故障解除并完成规定核对前拒绝新写 | 可用诊断继续读取 |

“控制受阻”是许可/连接/在途结果/保护等闸门状态，不需要增加一个可选操作模式；界面仍显示MANUAL/AUTO/AUTO_PAUSED及阻断原因。Edge内部记录`mode`、`active_source`、来源会话、切换代次、在途请求和阻断原因；来源/代次留在Edge，不恢复PLC多来源owner/epoch方案。切换代次用于使旧来源尚未执行的请求失效，不能通过网络重发恢复旧控制权。

### 3.2 什么才算“屏幕被使用”

只有经身份/权限、License、写点与操作类别、取值/保护条件及请求有效性检查，并被Edge受理的**新人工控制意图**触发接管。包含核定的启动、停止、调频，以及明确列入人工干预的参数修改；仅选择设备、打开页面、查看趋势或修改尚未提交的输入框不算。

专用屏的正常Modbus读取、心跳、TCP保活、周期刷新、重复报文与后台宏均不用于自动抢权。普通Modbus报文本身不携带“真人点击”证明；只有核对屏工程后能确定来源于操作控件的地址/写序列才允许自动接管。若宏与真人操作共用相同地址/值，代理不能凭报文区分，须修改宏/绑定或增加可识别的操作协议，不能假装检测到了真人。新的同值点击与自动重试同样不能只靠MBAP事务号、源IP或到达时间区分；必须核定可识别新意图的协议或屏工程确实停止自动重发。无法证明时，该类写不开放自动接管，不能以时间窗口猜测。

HMI2仅把新的、显式用户操作经受认证的hmi-runtime提交；旧草稿、页面初始化、重连后的补发不得作为新接管。专用屏来源须结合核定网口/源网络限制，不单靠声称的IP；HMI2的Edge凭证由runtime持有，不交给浏览器。多TCP连接/多浏览器不能各自形成并行物理写入口。

### 3.3 正常操作与切换矩阵

| 当前情况 / 新事件 | Edge处理 | 切换结果 |
|---|---|---|
| 初次启动，状态核对与门禁通过 | 不重放旧意图、不授权算法；等待新的人工请求 | MANUAL，来源无 |
| 手动待操作，专用屏有效操作 | 受理该来源并执行本次命令 | MANUAL，专用屏 |
| 手动待操作，HMI2有效操作 | 受理该来源并执行本次命令 | MANUAL，HMI2 |
| 专用屏手动，HMI2新的有效操作 | 确认无旧在途请求且按钮操作已完整收尾后，撤销旧来源未发请求并接管 | MANUAL，HMI2，无须原屏同意 |
| HMI2手动，专用屏新的有效操作 | 与上一行完全对称 | MANUAL，专用屏，无固定屏幕优先级 |
| AUTO，任一屏有效启停/调频 | 停止产生/发送新AUTO；使旧未发AUTO失效；已发AUTO结果确认后执行新人工命令 | MANUAL，操作屏；不自动回AUTO |
| 任一手动状态，操作员明确启用AUTO | 核权限、PLC/数据/保护及执行链；确认无在途请求且按钮操作已完整收尾后取得算法写权限 | AUTO，Edge算法；从已接受目标无扰开始 |
| AUTO_PAUSED，原因恢复但无人操作 | 继续暂停；恢复连接或新数据本身不等于重新授权 | 保持AUTO_PAUSED |
| AUTO_PAUSED，条件齐全且明确重新启用AUTO | 建立新控制代次，丢弃旧目标，以实时状态重新计算 | AUTO，Edge算法 |
| AUTO_PAUSED，任一屏新的有效人工操作 | 核对人工所需闸门；原阻断若也影响人工则仍拒绝 | 通过后MANUAL，操作屏 |
| 任一模式，普通读取/心跳/刷新 | 返回数据，更新通信健康；不生成控制意图 | 来源和模式不变 |
| 非法值、未授权来源、未签收写点 | 拒绝且不下发、不排队待恢复 | 来源和模式不变 |
| 人工意图已被受理，但PLC拒绝/执行失败 | 明确显示失败；结果不确定则锁写；不得借失败恢复旧AUTO | 保持MANUAL，保留本次操作归属和结果 |
| 长时间没人操作 | 不因闲置本身改变模式或生成写入；既有AUTO按有效授权继续 | 手动继续手动；自动按原有效授权运行 |

“当前来源”只是下一次切换与审计依据，不是永久占有锁。HMI2无需先点击单独的“接管”按钮；正常有效人工操作就申请接管。进入自动则必须显式选择，不由屏闲置推断。

### 3.4 少见的同时操作与在途请求

Edge在受理/执行边界串行裁决，不按屏幕本地时间或IP排序。不能使用“最后到达的网络包一律覆盖”处理两屏争用。任一时刻最多一个完整PLC控制操作在途。

- 两屏普通人工操作重叠时，先受理的一次继续执行；另一屏返回忙/冲突，不排入稍后执行队列、不改变当前归属。完成后该屏再次发起**新的人工操作**即可取得控制权。异常后自动重发不能作为“再次人工操作”。
- 已发给PLC的命令不能撤回。AUTO被人工打断时先停止后续AUTO，等待当前结果；超时/结果未知锁写，人工命令不能偷偷补发。检查通过不代表可以跨过正在执行的PLC动作顺序。
- 按钮按下/松开、脉冲复位及需要顺序收尾的命令必须作为完整操作核定；在收尾之前不移交给另一屏。不能因换屏而丢失松开/复位，也不能擅自把任何写0当作安全停止。若此类操作尚不能完整跟踪，相关写点不开放。
- 切换时旧来源未发送命令全部失效，不能后来覆盖新来源。保留旧请求与取消/拒绝结果用于审计，不重放；新一代来源开始操作前必须重新核对PLC当前状态。
- 软件停止也是经核定的人工命令，不等同于独立急停；控制受阻/结果未知时不声称软件停止一定能送达，硬接线急停与PLC保护始终独立有效。

### 3.5 断线、故障与恢复矩阵

| 事件 | 模式 / 控制权 | 输出与恢复规则 |
|---|---|---|
| 当前手动屏断开或控制会话超时 | 撤销其会话和未发请求；确认无未知在途且无未收尾完整操作后回MANUAL待操作，另一屏可用新的有效操作接管 | 不转AUTO；若屏断开导致松开/复位缺失则冻结接管，按经签收的PLC超时/复位机制或维护核对处理，不擅自补写0；不得宣称屏断开即全停 |
| 当前手动屏短暂断线后恢复 | 读取状态并建立新会话，旧命令不能续发 | 重连本身不夺回控制权 |
| 非当前来源的屏断线/恢复 | 当前控制来源不变 | 不影响另一屏已有操作；读写恢复仍核门禁 |
| AUTO时一块或两块屏断开 | 按Edge本地自治设计，屏连接本身不是AUTO必要条件；仅当Edge/PLC、数据、许可及工艺保护持续有效时继续AUTO | 如工艺签收要求有人监护，则屏/监护丢失转AUTO_PAUSED；不得靠屏在线冒充监护。此工艺条件须在自动验收时核定 |
| 云端/外网断线 | 不直接转移本地控制权 | 本地Edge/PLC及当前许可仍有效才能继续；许可状态未知/失效按原License合同阻断 |
| 关键工艺数据过期/自动输入不可信 | 停止新AUTO，进入AUTO_PAUSED | 仅影响算法的缺失不自动放开人工；人工命令按自己的安全条件另核 |
| Edge与PLC通讯断开 | 停止全部新写，AUTO进入暂停；不建立HMI直连旁路 | 恢复后先读PLC；无未知在途才允许新人工命令；AUTO必须重新授权 |
| 写结果未知或代理journal未清 | 保持锁写，与当前显示MANUAL/AUTO_PAUSED分开 | 换屏、重启、重连、重新选模式都不能解除；核对现场结果后走维护流程 |
| Edge/API/执行器重启 | 失效旧会话/旧请求，回MANUAL待核对；不恢复旧AUTO | 已持久未知锁保留，重新读PLC；不自动启机/补写 |
| PLC重启或运行程序重新开始 | 停止新写、旧请求失效；AUTO暂停且不能自行恢复 | 核定重启识别信号并重读模式/保护/有效目标，确认无未知或未收尾操作后才受理新人工意图；上电输出由PLC签收逻辑决定，TCP在线或M1001翻转不证明执行会话连续 |
| PLC本地/检修限制或保护触发 | 相应控制闸门阻断，AUTO停止新下发并暂停 | 最终输出由PLC保护/顺控决定；检修锁仅人工解除，解除后不自动回AUTO |
| 最终撤掉专用屏 | 撤销专用屏身份/接入权限，HMI2成为唯一人工来源 | 仲裁仍在Edge，AUTO及PLC保护边界不变，须在迁移验收后执行 |

失联阈值、停机顺序、保持/降频策略按设备签收，不预设全停或全部保持。M1001只证明PLC侧活跃，不证明PLC已实现Edge失联监测。正常模式切换/重连从PLC已接受有效目标无扰衔接，保护动作优先；范围、单次/累计变化率、冷却与工艺约束持续生效。

### 3.6 状态显示与验收

HMI2显示实际模式、当前来源（专用屏/HMI2/自动/无）、最近切换原因及时间、在途/忙、阻断原因和请求结果；两屏观察同一PLC真实反馈。专用屏沿用原点表，不凭空承诺原画面能显示新增Edge控制权字段；没有对应控件时先以核定的通讯异常/操作失败提示拒绝结果，是否增加状态位由屏工程另定。

验收至少覆盖矩阵全部事件，尤其两屏双向接管、两屏同时点击、按下/松开跨切换、后台宏/重连重发不抢权、人工打断在途AUTO、旧回执晚到、屏断线与PLC断线区别、未知结果跨重启锁存，以及无条件恢复AUTO的拒绝。没有这些证据不得把代理初版称为完整三来源控制仲裁。

## 4. 命令、接受结果与设备反馈

分别呈现请求收到、PLC接受/拒绝、输出状态、设备真实运行反馈。Modbus回显只证明通讯处理，Y不能证明电机动作，D/AO不能证明VFD实际频率；无反馈则未知。

最小接口核定设备/动作、请求身份与会话有效期、防重放、类型/倍率/范围、允许模式、拒绝原因和读回。保留既有Edge鉴权/签名/白名单/审计，不照搬旧D5100–D5699整包，也不开放任意地址代理。

## 5. 后续工艺调节与验收

稳定成品湿度的工艺策略归Edge，快速设备保护和顺控归PLC。先确认湿度含义/倍率、电流温度真实设备绑定和频率目标/反馈，再核定控制输入输出。新表D17–D21、D42、X003/X005/X006与旧配置冲突，不能把旧canonical名直接作有效算法输入。

数据不足或响应不符即暂停自动下发；算法不直写PLC。算法增强、VFD通讯扩展和人员安全认证不因本轮被自动纳入实施。

当前PLC/屏工程核对 → 单入口/最小接口签收 → 隔离正负向验证（停止、冲突、过期、断线、重启、结果未知）→ 指定现场窗口逐点验收 → 已通过点进入白名单。专用屏全部必要功能迁至HMI2并验收后撤除，不恢复HMI direct。

## 6. 专用屏代理实施

专用屏沿用原寄存器地址，以标准Modbus TCP经Edge读写PLC。代理实现与工程交接见[接入说明](../plc/hmi-modbus-proxy.md)。代理模式互斥停用旧MQTT/D5100物理写入，API明确拒绝旧六SP写和AUTO授权；原DAQ只读采集保留。新自动调节和HMI2写入待地址/语义核定后接入统一代理执行边界，不同时运行旧写链。专用屏获准操作通过原API控制权限/License门禁触发MANUAL接管，未知在途结果拒绝写且不自动恢复AUTO。

当前实现状态：`73dbd75`已具备专用屏代理、受控MANUAL交接、旧未发AUTO失效、在途等待与未知结果持久锁。尚未具备新写路径的HMI2控制、三来源统一`active_source`/会话、双屏冲突与完整按钮收尾、可证明的新人工意图/重试区分、自动算法新点位写入及上述完整矩阵。现有代理按请求排队的行为不能冒充本节“两屏重叠拒绝”已经实现；这些是下一阶段实现/验收项。本次仅补充设计，不开放现场控制。
