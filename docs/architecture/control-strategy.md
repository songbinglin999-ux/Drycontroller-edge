# 🎛 控制策略说明（Control Strategy）

> 版本：v1.0  
> 关联模块：`ai-ctrl-optimizer`、`edge-daq`、PLC 控制逻辑  
> 关联文档：`system-overview.md`、`data-flow.md`、`tag-definition-standard.md`

---

## 1. 控制目标与边界

### 1.1 控制目标

- 在满足 **安全与工艺约束** 的前提下：
  - 使成品含水率稳定在工艺目标区间内  
  - 尽量降低能耗与生产波动  
  - 提升生产线自动化与稳定性

### 1.2 控制边界

- 系统当前阶段以 **“AI 建议 + 人工确认”** 为主：  
  - AI 给出链速、抽风频率等 setpoint 建议  
  - 最终是否执行由操作员在大屏/上位机确认  
- 未来预留 **闭环自动控制模式**，但仍需 PLC 侧安全联锁兜底。

---

## 2. 控制对象与可调参数

主要控制对象与可调参数包括：

- **链速（Chain Speed）**
  - 影响物料在烘干区停留时间  
  - Tag 示意：`*_CHAIN_SPEED_SP` / `*_CHAIN_SPEED_PV`
- **抽风机频率（Fan Frequency）**
  - 影响排湿能力与温度分布  
  - Tag 示意：`*_FAN_FREQ_SP` / `*_FAN_FREQ_PV`
- **预烘干工况相关参数**（如有）
  - 如预烘干温度设定、风门开度等（视实际 PLC 实现）

实际 Tag 名与含义请参照：`docs/plc/tag-definition-standard.md`。

## 3. 控制模式

### 3.1 人工模式（Manual）

- 操作员通过上位机/面板直接修改 PLC 内的 setpoint  
- 系统主要用于采集、展示与记录，不直接改写 setpoint  
- 适用场景：
  - 初次投产 / 试车  
  - AI 模型尚未充分验证  
  - 故障或异常情况下的紧急接管

### 3.2 AI 建议 + 人工确认模式（Semi-auto）

- 流程：

```text
实时数据 + AI 含水率估计
   ↓
ai-ctrl-optimizer 计算最优 setpoint 建议
   ↓
通过 MQTT 发布控制建议（control/suggestion/#）
   ↓
edge-api / 大屏展示建议值
   ↓
操作员确认后 → 通过 /control/set 下发到 PLC
```

- 特点：
  - 控制建议由 AI 和规则共同计算  
  - 人工有最终决定权，减少“黑盒”风险

### 3.3 全自动模式（Auto，预留）

- 未来可选模式：  
  - edge-api 在人工授权的 autopilot 层级下，把 suggestion 转成 signed command
  - `edge-daq` 只消费 signed command 写 PLC，AI 不直接写 PLC
  - 仍需 PLC 侧设定安全上下限与联锁  
- 启用前必须：
  - 在现场充分测试  
  - 与工艺与安全部门共同评估后决策

## 4. 控制安全边界与限幅策略

所有控制策略都需满足以下约束（配置集中在 `configs/limits.yaml`）：

- **物理上下限约束**
  - 如：链速 ∈ \[MIN_SPEED, MAX_SPEED\]  
  - 抽风频率 ∈ \[MIN_FREQ, MAX_FREQ\]
- **变化率约束**
  - 每次调整的幅度不超过 `MAX_DELTA`  
  - 一定时间窗口内的累计变化不超过 `MAX_ACCUM_DELTA`
- **安全联锁约束**
  - 温度、扭矩等超过安全阈值时，禁止继续提升链速/风量  
  - 某些故障状态下强制切换到人工模式

AI 输出的建议 setpoint 必须先经过上述限幅与安全规则过滤，再展示/下发。

## 5. ai-ctrl-optimizer 策略逻辑（概述）

### 5.1 输入

- 来自 MQTT / InfluxDB 的实时工艺数据：
  - 当前各段温度、尾气温度、料温、链速、风机频率等  
- 来自 `ai-softsensor` 的含水率估计与置信度  
- 来自配置库（PostgreSQL/`limits.yaml`）的：
  - 目标含水率区间  
  - 上下限与变化率约束  
  - 不同原料/工况的策略参数（如权重、目标偏好）

### 5.2 输出

- 建议链速 setpoint  
- 建议抽风频率 setpoint  
- 可选：执行优先级与建议执行时机（立即/缓慢调整）

### 5.3 链速控制逻辑

- 当含水率偏高或出口料温偏高时：
  - 优先 **降低链速**，延长物料在烘干区的停留时间  
  - 降速幅度受 `MAX_DELTA_SPEED` 与工艺约束限制  
- 当含水率偏低且品质允许时：
  - 适当 **提高链速**，在不牺牲品质的前提下降低能耗、提升产能  
- 在风量/热量不足或安全风险存在时（如温度过低/过高）：
  - 暂停提速或适当减速，优先保障安全与稳定

### 5.4 抽风控制逻辑

- 当含水率偏高、尾气温度偏高时：
  - 适度提升抽风频率，提高排湿能力  
- 当含水率接近下限或温度偏低时：
  - 避免过高抽风导致能耗上升与工艺过干  
- 抽风频率调整同样受 `MAX_DELTA_FREQ` 与安全约束控制

### 5.5 温度控制边界

- AI 与控制策略 **不直接调节炉膛火力**，但会在以下场景中尊重温控边界：
  - 当任一关键温度 Tag 接近 `TEMP_MAX_SAFE` 时，禁止增加链速和风量  
  - 当温度持续低于工艺下限时，提示人工检查炉膛/燃烧系统  
- 具体温控上下限与报警逻辑在 PLC 程序和 `limits.yaml` 中共同定义。

### 5.6 预烘干热耦合逻辑

- 预烘干段利用尾气/余热，其工况变化会影响后续主烘干段：
  - 尾气温度、预烘干出口料温作为特征输入参与链速与抽风决策  
  - 当预烘干能力不足（出口料温偏低）时，控制策略会更保守地提升链速  
- 未来可进一步在 `ai-ctrl-optimizer` 中显式建模“预烘干 ↔ 主烘干”的能量耦合关系。

### 5.7 综合策略示例

- 规则 + 优化混合方式：
  - 当含水率偏高 → 优先降低链速或提高风量  
  - 当含水率偏低 → 适当提高链速以提升产能  
  - 同时考虑炉温、预烘干能力等限制，避免过度调整

## 6. 控制链路实现要点

### 6.1 控制建议发布

- Topic 示意：`control/suggestion/{line}`  
- Payload 示例：

```json
{
  "line": "L1",
  "timestamp": "2025-01-01T12:00:00Z",
  "suggestions": [
    { "tag": "L1_DRY2_CHAIN_SPEED_SP", "value": 1.8 },
    { "tag": "L1_FAN1_FREQ_SP", "value": 35.0 }
  ],
  "reason": "moisture_high",
  "ai_confidence": 0.92
}
```

### 6.2 控制执行（/control/set）

- `edge-api` 接口负责：
  - 校验 Tag 与 Value 的合法性（范围、步长、当前模式）  
  - 记录操作日志（操作者、理由、前后值）  
  - 将合规命令转换为 MQTT 消息，交给 `edge-daq` 写入 PLC
  - autopilot 也不绕过 edge-api 的 range guard / 签名 / 审计

### 6.3 AI 控制建议如何平滑下发

- **防抖**：仅当连续多次建议方向一致、且偏差超过阈值时才生成控制建议  
- **缓变**：对比当前 setpoint 与 AI 建议值，按最大步长/变化率缓慢逼近，而非一次性跳变  
- **节流**：限制单位时间内的调整次数，避免“抖动式”频繁调节  
- **可见性**：大屏上同时展示当前 setpoint 与 AI 目标值，方便操作员理解和判断

## 7. 降级与回退策略

当发生以下情况时，控制策略需要自动或人工降级：

- AI 推理异常或置信度持续过低 → 停止使用 AI 输出，仅采用简单规则或人工经验  
- 通讯异常（PLC / MQTT） → 暂停下发新 setpoint，保持当前稳态  
- 发现控制策略导致工艺波动增大 → 人工切回纯手动模式，并通知算法/工艺团队

相关降级与自愈流程详见：`self-healing.md` 与 `risk-assessment.md`。

---

## 8. 现场应用建议

- 在项目早期：
  - 先启用“AI 建议 + 人工确认”模式，积累经验与数据  
  - 将 AI 建议与实际人工操作进行对比评估  
- 在策略成熟后：
  - 可在部分时段/部分工况下试点半自动控制  
  - 针对每种物料类型和工况建立相应的策略参数配置
