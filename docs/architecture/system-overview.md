# 1. 🎯 系统定位

本系统是一个 **用于“双段烘干 + 发酵仓 + 尾气余热利用 + 气流干燥” 生产线的智能控制与数字化集成平台**。

系统核心能力：

* 工控实时数据采集（PLC → MQTT → InfluxDB）
* 含水率软测量（AI）
* 控制策略优化（链速/抽风量 setpoint 建议）
* 尾气余热预烘干耦合逻辑处理
* 数据治理与指标管理
* 数字孪生提供的大屏实时可视化
* 本地化、可脱网运行
* 支持 OTA 远程升级
* 自愈与自动恢复能力

系统工作模式为：

> **“边缘计算（Edge）为核心 → 不依赖云端 → 分层架构 → 具备自维护能力 → 可规模化部署”。**

# 4. 🔧 模块拆分与职责说明

## 4.1 edge-api（统一 API 服务）

* 供大屏、Web、运维工具调用
* 聚合各服务的数据
  -暴露 REST + WebSocket
* 负责设备状态、实时数据、历史曲线、AI 推理结果

## 4.2 edge-daq（PLC 数据采集）

* 与 PLC 建立连接（Modbus/TCP）
* 采集温度、料温、风机频率、扭矩等
* 校验数据、滤波
* 发布到 MQTT
* 提供模拟器（未接 PLC 时也能跑通系统）

## 4.3 ai-softsensor（含水率软测量）

* 订阅 MQTT 点位
* 输入特征预处理
* ONNX 模型推理
* 含水率估计 + 置信度
* 推理失败自动回退老模型
* 结果写入 InfluxDB 和 MQTT

## 4.4 ai-ctrl-optimizer（控制策略优化）

* 接收软测量结果
* 根据实时温度/尾气/料温计算
* 输出最佳 setpoint（链速、抽风频率）
* 建立控制约束（上下限、速度变化率）
* 提供 AI 控制与人工控制切换

## 4.5 license-service（授权）

* 加密狗通信
* 校验授权状态
* 控制 AI 功能开关
* 提供统一查询接口

## 4.6 edge-monitor（系统健康监控）

* 检查所有服务 `/health`
* 监控 CPU / 内存 / 磁盘 / Docker / 网络
* 自动自愈（服务重启 / 模型回滚）
* 推送状态到 MQTT 和 API

## 4.7 InfluxDB（时序数据库）

* 存储所有采集点、AI 输出
* 大屏用它做历史曲线

## 4.8 PostgreSQL（配置库）

* 点位定义
* 模型版本信息
* 报警规则
* 用户/权限（预留）

# 5. 🔄 数据流说明

## 5.1 PLC → edge-daq → MQTT → InfluxDB

主要实时点包括：

* 一段烘干区温度
* 二段烘干区温度
* 尾气温度（对应预烘干热源）
* 预烘干出口料温
* 料斗绞龙扭矩
* 链速
* 风机频率
* 炉温
* 成品人工含水率

## 5.2 AI 模型数据流

```
edge-daq → MQTT → ai-softsensor → MQTT/InfluxDB → ai-ctrl-optimizer → API
```

## 5.3 控制策略数据流

```
ai-ctrl-optimizer → API → 大屏/PLC（未来可实现）
```

# 6. 🔁 自维护与自愈机制（Self-Healing）

系统自维护从四个层面展开：

### 6.1 服务自愈

* 每个服务提供 `/health`
* edge-monitor 定期调用
* 健康失败 → 自动重启

### 6.2 数据自愈

* PLC 自动重连
* 数据异常 → AI 自动降级

### 6.3 AI 自愈

* 模型加载失败 → 回滚到上一版本
* 推理异常 → 暂停推理

### 6.4 OTA 自愈

* 升级失败自动回滚
* 升级成功写入版本记录

完整规范详见：
`docs/architecture/self-healing.md`

# 7. 🔐 安全体系

### 7.1 网络安全

* 工控机不直接接公网
* 大屏主机作为跳板机
* 内网通信所有端口白名单控制

### 7.2 授权安全

* 加密狗 + license-service 双验证
* 服务层面基于 token 校验

### 7.3 配置安全

* 所有 `.yaml` 需通过 Schema 校验
* 配置热更新必须通过 API 变更日志记录

# 8. ⚙️ 配置管理体系

### 配置结构位于：

```
configs/
  tags.yaml
  ai-config.yaml
  limits.yaml
  qos.yaml
```

原则：

* 所有参数外置配置化
* 修改前必须通过验证工具
* 修改记录写入 PostgreSQL
* 配置更新后服务自动 reload（不重启）

# 9. 🤖 AI 模型管理与架构

模型版本目录：

```
models/
  v1.0.0/
  v1.1.0/
  v1.2.0/
```

要求：

* 全部使用 ONNX 格式
* 每次升级必须保留历史版本
* 模型推理服务支持动态切换模型
* 模型异常 → 自动回退

AI 推理流程：

```
MQTT 输入 → 特征构建 → 推理 → 校验 → 发布结果
```

# 11. 👁 系统可观测性

系统同时具备以下可观测能力：

* **指标（Metrics）**：资源占用、服务心跳
* **日志（Logs）**：结构化 JSON
* **事件（Events）**：PLC 中断、AI 降级、OTA 回滚

* 烘干链路状态
* 软测量趋势
* 控制策略变化
* 服务健康状态
* 资源运行状态

# 13. 🚨 降级与故障策略

| 场景           | 降级动作       | 影响           |
| ------------ | ---------- | ------------ |
| PLC 断连       | AI 暂停、显示报警 | 不改变 setpoint |
| AI 推理失败      | 回退模型       | 稳态运行         |
| AI 控制输出异常    | 进入人工模式     | 需人工调整        |
| MQTT 长时间中断   | DAQ 缓存数据   | 可能丢短期数据      |
| InfluxDB 不可用 | 仅保留实时      | 无历史记录        |
