# 长期偏移监控与制造辅助分析设计

> 状态：v0.1 草案（2026-06-08 CST）
> 范围：工艺健康 / 制造辅助 / 质量追溯，不参与实时控制
> 点位来源：`docs/plc/io-map.html` + `configs/tags.yaml` 当前 48 个只读 I/O 点
> 相邻文档：`docs/control-core/e-line-diagnosis-rules.md`
> 自适应治理：`docs/algorithm-governance/self-evolution-design.md`

---

## 0. 定位

长期偏移监控不是 PLC 控制，也不是 `control-core` 的秒级/分钟级诊断。它看的是小时、天、周级趋势，用来提前发现制造、装配、维护、工艺稳定性问题。

典型输出：

```text
过去 14 天，在相近运行负荷下，滚筛 M12 正常运行电流中位数上升 18%。
建议排查筛面堆积、机械阻力、轴承/传动状态或装配偏移。
```

它解决的问题是“这条线是不是越来越难跑、越来越耗能、越来越不稳定”，不是“当前这一分钟是否堵料”。

---

## 1. 与其他文档的边界

| 文档区域 | 时间尺度 | 关注点 | 是否写 PLC |
|---|---|---|---|
| `docs/plc/` | 实时 / 硬保护 | 点位、地址、安全联锁、PLC 报警 | PLC 自己执行 |
| `docs/control-core/` | 秒级 / 分钟级 | 堵料、空转、过载、供热不足、湿度异常原因 | 不写 |
| `docs/process-intelligence/` | 小时 / 天 / 周级 | 长期漂移、退化趋势、制造问题、质量追溯 | 不写 |

长期偏移可以引用 control-core 的诊断结果作为上下文，但不替代实时诊断。实时异常窗口不应直接进入长期正常基线，避免把故障学习成“正常”。

## 2. 输入范围

v0.1 只依赖当前 48 个 I/O 位号和已有算法输出：

- 电机运行与电流：`M1-15`、`I_M1-15`
- 变频 / 风量反馈：`VFM1-3`、`VF1-3`
- 温度：`FTT1-3`、`TT1-2`
- 料位 / 湿度：`LL1-6`、`MT1`
- softsensor 输出：`MOISTURE.PREDICTED`
- control-core 输出：诊断 code、severity、confidence、evidence window
- 未来可选上下文：班次、配方、原料批次、离线化验、维护记录

未来上下文不是 v0.1 前置条件。没有班次/配方时，算法只按可观测工况做“相近运行状态”对比。

## 3. 核心对象

### 3.1 机械负载漂移

问题：同样运行状态下，某台设备电流基线逐周升高，可能意味着机械阻力、装配偏移、筛面堆积、轴承/传动退化。

| 对象 | 指标 | 典型提示 |
|---|---|---|
| 输送 `M1/M2/M4/M6/M8/M10/M11/M13` | 正常运行电流中位数、P75、波动度 | 输送阻力变大、皮带/链条/螺旋状态变差 |
| 主机 `M3/M5/M7/M9` | 相近给料反馈下的电流基线 | 主机负载变重、内部阻力或物料状态变化 |
| 滚筛 `M12` | 正常运行电流中位数、波动度、与 `M11/M13` 的相关性 | 筛面堆积、机械阻力、出料不畅趋势 |
| 锅炉相关 `M14/M15` | 电流基线、燃料料位事件后的响应 | 燃料供给或锅炉辅助机构退化 |

### 3.2 热效率漂移

问题：同样风机/给料反馈下，温度越来越难达到，或湿度控制越来越差。

| 对象 | 指标 | 典型提示 |
|---|---|---|
| 主机1 | `VFM1/VF1/FTT1/I_M3` 的关系 | 风路、换热、给料负荷变化 |
| 主机2 + 锅炉1 | `TT1 -> FTT2` 响应、`VF2`、`I_M5` | 锅炉1供热效率或热风传递退化 |
| 主机4 + 锅炉2 | `TT2 -> FTT3` 响应、`VF3`、`I_M9` | 锅炉2供热效率或末段干燥能力退化 |

输出例子：

```text
最近 7 天，TT2 与 FTT3 的温差扩大，且 VF3 反馈稳定。
建议检查锅炉2到主机4的热风通路、换热效率或温度传感器状态。
```

### 3.3 质量与湿度漂移

问题：`MT1`、softsensor、离线化验之间长期偏离，可能是传感器漂移、模型漂移、原料状态变化或工艺能力下降。

| 漂移 | 佐证 |
|---|---|
| `MT1` 长期偏离 softsensor | `MT1` 单独漂移，其他工况稳定 |
| softsensor 长期偏离离线化验 | 模型需要重训或特征时延需要校准 |
| 湿度波动变大 | 温度/风量/给料波动、滚筛/出料异常增多 |
| 同等热量下湿度变高 | 原料状态变化、干燥效率退化、负荷偏重 |

### 3.4 稳定性退化

问题：均值没明显变坏，但波动变大，制造一致性下降。

指标：
- 正常窗口内电流/温度/湿度的方差、P95-P5、MAD。
- control-core 诊断频次：同一设备 warning 频次是否逐周升高。
- 异常恢复时间：从异常提示到回归正常的持续时间是否变长。
- 设备联动一致性：上下游电流相关性是否变差。

## 4. 基线与阈值

长期偏移阈值不是 PLC 安全阈值，也不是实时控制阈值。这里的阈值是制造辅助分析参数，用来判断“长期趋势是否值得关注”。

### 4.1 冷启动

PLC 数据刚接入时，先跑影子分析，不给强结论：

- 先积累至少 7 天运行数据，建立初始基线。
- 基线只取“稳定运行窗口”：设备运行、数据 fresh、无高置信 control-core 异常。
- 每台设备单独建画像，不能共用统一电流阈值。
- 只输出低级 observation，不生成制造问题结论。

### 4.2 稳健基线

每个对象维护多个窗口：

| 窗口 | 用途 |
|---|---|
| 8 小时 | 班次级波动观察 |
| 24 小时 | 日级制造稳定性 |
| 7 天 | 周级基线 |
| 14 / 30 天 | 慢性退化趋势 |

建议口径：

```text
baseline = 稳定窗口中位数
spread = MAD 或 P75-P25
drift_score = 当前长窗口 baseline 相对历史健康 baseline 的偏移幅度
```

### 4.3 告警分级

| 等级 | 判断 | 输出 |
|---|---|---|
| observe | 漂移有苗头，但样本少或佐证弱 | 仅记录趋势 |
| attention | 漂移持续，且跨多个窗口成立 | 工艺/维护关注 |
| investigate | 漂移显著，并有上下游或质量佐证 | 建议安排检查 |
| critical | 长期漂移已伴随频繁实时异常或质量风险 | 建议停机窗口内重点排查 |

分级只影响制造辅助提示，不触发 PLC 动作。

## 5. 自适应策略

长期偏移允许自适应，但必须受控。跨 E 线诊断阈值、G 线长期基线和 softsensor 候选模型的共同治理，见 `docs/algorithm-governance/self-evolution-design.md`；本节只保留 G 线偏移监控的局部原则。

允许自动更新：
- 正常运行基线的候选版本。
- 每台设备的波动范围、稳定窗口特征。
- “相近工况”的聚类边界。

不允许自动更新：
- PLC 安全阈值、联锁、急停、上电默认。
- edge-api 控制写入 range guard。
- `actionable=false` / 自动控制权限。
- 已确认异常期间的数据不能被自动吸收到健康基线。

更新流程：

```text
旧基线 -> 新候选基线 -> shadow 对比 -> 质量/误报指标改善 -> 人工确认 -> 生效
```

每次基线更新必须有版本：

```text
process-baseline/e-line-v20260608.yaml
```

记录内容：
- 生效时间、训练窗口、排除的异常窗口。
- 每个对象的 baseline、spread、样本数。
- 与上一版本相比的变化。
- 回滚目标版本。

## 7. v0.1 实现顺序

| 顺序 | 内容 | 验收 |
|---|---|---|
| 1 | 定义稳定运行窗口过滤 | 异常窗口不会进入长期健康基线 |
| 2 | 单设备电流基线漂移 | 覆盖 `I_M1-15`，输出 observe/attention |
| 3 | 滚筛专项 | 覆盖 `M11/M12/M13` 与 `I_M11/I_M12/I_M13` |
| 4 | 热效率漂移 | 覆盖 `TT1/TT2`、`FTT*`、`VF*` |
| 5 | 湿度 / softsensor / 化验偏移 | 等离线化验流程后启用 |
| 6 | 基线候选版本与人工确认 | 支持 shadow 对比和回滚 |

## 8. 待补输入

这些输入会显著提高制造辅助价值，但不是 v0.1 前置：

- 配方 / 产品批次 / 原料含水率。
- 班次、操作员、维护记录。
- 离线化验结果。
- 设备维护与更换件记录。
- 能耗或蒸汽/燃料消耗计量。

没有这些输入时，v0.1 只做设备与工艺信号自身的相对漂移，不对原料、班组或制造批次下强结论。
