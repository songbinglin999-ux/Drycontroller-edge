# E 线控制核心规则诊断设计

> 状态：v0.1 草案（2026-06-08 CST）
> 范围：pre-AI 可解释诊断 / 建议，不做自动控制
> 点位来源：`docs/plc/io-map.html` + `configs/tags.yaml` 当前 52 个只读 I/O 点
> 关联边界：`docs/plc/io-and-control-contract.md`、根 `architecture-audit-2026-05-06.md` E 线
> 自适应治理：`docs/algorithm-governance/self-evolution-design.md`

---

## 0. 设计边界

本文定义 E 线控制核心在当前阶段能做什么、不能做什么。这里的“控制核心”不是 PLC 点位文档，也不是黑盒 AI/MPC；它是基于现场 52 个只读位号、历史窗口和 softsensor 输出，给出可解释诊断、分级提示和人工处置建议的规则层。

**固定范围**：
- 只使用当前 `io-map` / `tags.yaml` 里的 52 个 I/O 位号：`LL1-6`、`FTT1-3`、`T_OUT2/T_OUT4`、`TT1-2`、`MT1`、`I_M1-16`、`M1-16`、`VFM1-3`、`VF1-3`。
- `M*`、`VFM*`、`VF*` 全部按 PLC 反馈值处理；edge 观察它们，不写它们。
- 输出诊断、证据、置信度、建议文案和阻断原因；`actionable=false`。
- 阈值先按相对基线和趋势写设计，真实电流/温度/湿度阈值等现场数据后再标定。

**明确排除**：
- 不纳入 `io-map.html` 里的“建议补充点位”；v0.1 不依赖零速、热继、VFD 故障、安全门、轴承温度、产品温度等新增信号。
- 不保留旧版 `DRYER1.*` / `DRYER2.*` / `CHAIN.SPEED` / `FAN.SPEED` 推荐语义。
- 不自动签发 PLC 写入命令；`P0-SAFETY`、`P0-CTRL-NAK`、`P0-CTRL-MODE` 关闭前，任何建议都只能展示给人。
- 不把“含水率高”简化成“提高链速”。含水率异常必须先做原因分析。

## 1. 工艺拓扑

规则必须先理解上下游关系，再看单个点位。v0.1 按下面拓扑建图：

```text
料斗1 -> M1 -> 料斗2(LL1) -> M2 -> 料斗3(LL2)
  -> VFM1 -> 主机1(M3, VF1, FTT1, I_M3)
  -> M4 -> 料斗4(LL3)
  -> VFM2 -> 主机2(M5, VF2, FTT2, T_OUT2, I_M5) <- 锅炉1(M15, LL5, TT1)
  -> M6 -> M7 -> 发酵仓(M8, I_M8)
  -> M9 -> 料斗5(LL4)
  -> VFM3 -> 主机4(M10, VF3, FTT3, T_OUT4, I_M10) <- 锅炉2(M16, LL6, TT2)
  -> M11 -> 料斗6(MT1)
  -> M12 -> 滚筛(M13, I_M13)
  -> 料斗7 -> M14 -> 出料
```

| 区段 | 关键位号 | 规则用途 |
|---|---|---|
| 前段输送 | `M1/M2`、`I_M1/I_M2`、`LL1/LL2` | 入料连续性、前段堵料/断料 |
| 主机1 | `VFM1`、`M3/I_M3`、`VF1`、`FTT1` | 给料-负载-风量-温度匹配 |
| 主机2 + 锅炉1 | `VFM2`、`M5/I_M5`、`VF2`、`FTT2`、`T_OUT2`、`M15/I_M15`、`LL5`、`TT1` | 二段负载、供热与出料蒸汽/排湿状态判断 |
| 发酵仓 | `M7/I_M7`、`M8/I_M8` | 中段负载观察；当前无独立温度/风量点，判断要保守 |
| 主机4 + 锅炉2 | `VFM3`、`M10/I_M10`、`VF3`、`FTT3`、`T_OUT4`、`M16/I_M16`、`LL6`、`TT2`、`MT1` | 末段干燥、排湿能力与成品趋势判断 |
| 出料 + 滚筛 | `M11/I_M11`、`M12/I_M12`、`M13/I_M13`、`M14/I_M14`、`MT1` | 出料堵塞、滚筛负载、末端湿度异常 |

## 2. 通用特征

所有规则先抽同一批基础特征，避免每类诊断各写一套口径。

| 特征 | 口径 | 用途 |
|---|---|---|
| `fresh` | 最近值在允许时延内，历史窗口覆盖足够 | 防止用旧数据误判 |
| `running` | 对应 `M*` 反馈为运行 | 区分停机、空转、负载异常 |
| `current_now` | `I_M*` 最新值 | 单点负载状态 |
| `current_base_5m` | 5 分钟中位数或稳健均值 | 相对负载基线 |
| `current_rise_30s` | 30 秒内电流斜率 / 增量 | 堵料、卡滞、突增负载 |
| `current_sustained_high` | 当前电流持续高于近期基线 | 过载、下游不畅 |
| `current_sustained_low` | 运行状态下电流持续低于近期基线 | 空转、断料、皮带无料 |
| `level_transition` | `LL*` 在窗口内是否变化 | 判断料斗是否真的进/出料 |
| `feedback_mismatch` | 给料/风量反馈与主机电流、温度走势不匹配 | 工况异常或传感器异常 |
| `moisture_trend` | `MT1` 和 `MOISTURE.PREDICTED` 的趋势 | 湿度偏高原因分析 |

阈值策略：
- v0.1 先用“相对基线 + 持续时间 + 上下游佐证”，不写死安培/温度/湿度绝对值。
- 现场数据回来后再把每台电机的额定电流、空载电流、正常工况区间写进配置。
- 没有上下游佐证时，诊断降置信度，只输出“观察/检查”级建议。
- 自适应只能生成候选诊断参数，必须按 `docs/algorithm-governance/self-evolution-design.md` 走 shadow 对比、人工确认和版本化回滚。

## 3. 诊断类别

### 3.1 输送堵料 / 下游不畅

覆盖对象：`M1/M2/M4/M6/M9/M11/M12/M14/M7` 及对应 `I_M*`。

| 规则 | 触发线索 | 置信度 |
|---|---|---|
| `conveyor_current_rising` | 运行中，当前电流相对 5 分钟基线快速上升 | 中 |
| `conveyor_sustained_high` | 运行中，电流持续高于近期基线 | 中 |
| `downstream_not_accepting` | 下游料位不变化或下游设备电流也高 | 高 |
| `upstream_pushes_downstream_blocks` | 上游在送料，下游负载升高且料位/出料无明显变化 | 高 |

建议文案方向：
- “检查下游入口、料斗、滚筛或出料口是否堵塞。”
- “先确认 PLC/现场是否已有过流或卡料报警，再处理机械堵塞。”
- “不要直接建议提高链速；堵料场景下提高输送会放大风险。”

### 3.2 空转 / 断料

覆盖对象：前段输送、给料反馈 `VFM1-3`、主机电流 `I_M3/I_M5/I_M8/I_M10`、料位 `LL1-4`。

| 规则 | 触发线索 | 置信度 |
|---|---|---|
| `running_low_load` | 运行中电流持续低于近期基线 | 中 |
| `upstream_no_material` | 上游料位无料或长时间无变化 | 中 |
| `feed_feedback_low` | 对应 `VFM*` 反馈低，主机电流也低 | 高 |
| `no_level_progress` | 上游运行但下游料位无有效变化 | 高 |

与堵料的区分：
- 堵料通常是运行电流升高、下游不接受物料。
- 空转/断料通常是运行电流降低、上游无料或给料反馈低。

建议文案方向：
- “检查上游料斗是否缺料、给料机构是否未实际送料。”
- “确认对应给料反馈和现场皮带/螺旋是否空转。”

### 3.3 主机负载过高

| 主机 | 关键位号 | 主要判断 |
|---|---|---|
| 主机1 | `M3/I_M3`、`VFM1`、`VF1`、`FTT1` | 给料过重、风量不足、温度不足、机械负载升高 |
| 主机2 | `M5/I_M5`、`VFM2`、`VF2`、`FTT2`、`T_OUT2`、`TT1` | 二段给料/风温/出料蒸汽/锅炉1供热匹配 |
| 发酵仓 | `M8/I_M8` | 仅做负载趋势；缺独立温度/风量点，避免强结论 |
| 主机4 | `M10/I_M10`、`VFM3`、`VF3`、`FTT3`、`T_OUT4`、`TT2`、`MT1` | 末段负载、锅炉2/风量、出料蒸汽与最终湿度关联 |

核心规则：
- 主机电流高 + 给料反馈高：优先判断给料负荷偏高。
- 主机电流高 + 风温低或风量反馈低：优先判断干燥能力不足导致物料负荷偏重。
- 主机电流高 + 上下游输送也高：优先判断全段物料堆积或下游不畅。
- 主机电流高但运行/反馈数据缺失：只输出“主机负载异常观察”，不下强原因。

建议文案方向：
- “人工评估是否降低给料，先检查对应主机入口和下游通畅。”
- “检查风量反馈、风温和锅炉温度是否支持当前负荷。”
- “发酵仓 缺少温度/风量佐证，建议按负载趋势提示，不做温度原因定性。”

### 3.4 滚筛负载异常

覆盖链路：`M12/I_M12 -> M13/I_M13 -> M14/I_M14`。

| 规则 | 触发线索 | 置信度 |
|---|---|---|
| `screen_current_high` | `M13` 运行且 `I_M13` 持续高于近期基线 | 中 |
| `screen_downstream_block` | `I_M13` 高，同时 `M14/I_M14` 也异常或出料不畅 | 高 |
| `screen_upstream_overfeed` | `I_M12` 高、`I_M13` 高，说明滚筛入口负荷偏大 | 高 |
| `screen_low_load` | `M13` 运行但 `I_M13` 持续低 | 中 |

建议文案方向：
- “检查滚筛筛面、出料口和下游输送是否堆料。”
- “若上游 M12 电流同步升高，优先看滚筛入口负荷。”
- “若滚筛低负载且上游也低，优先看断料，不报堵料。”

### 3.5 供热不足 / 风量异常

覆盖位号：`TT1/TT2`、`FTT1/FTT2/FTT3`、`T_OUT2/T_OUT4`、`VF1/VF2/VF3`、`LL5/LL6`、`M15/I_M15`、`M16/I_M16`。

| 规则 | 触发线索 | 置信度 |
|---|---|---|
| `boiler_temp_low` | `TT1` 或 `TT2` 低于自身近期正常基线 | 中 |
| `hot_air_temp_low` | `FTT*` 低且对应主机负载/湿度异常 | 高 |
| `outlet_steam_high` | `T_OUT2` 或 `T_OUT4` 高，且对应风机反馈/湿度/主机负载异常 | 高 |
| `air_feedback_low` | `VF*` 反馈低，风温或湿度同步异常 | 高 |
| `fuel_supply_suspect` | `LL5/LL6` 异常，且锅炉温度/相关电流走低 | 中 |

对应关系：
- `TT1` 主要服务主机2 供热判断；`TT2` 主要服务主机4 供热判断。
- `FTT1/2/3` 是各干燥段风温反馈；`VF1/2/3` 是风量/风机反馈。
- `T_OUT2/T_OUT4` 是主机2/主机4出料口温度，主要反映蒸汽量、排湿状态和物料出段热状态；它们是 edge 算法输入，不是 PLC 温控 PV。
- `LL5/LL6` 是锅炉燃料料位线索，只能作为供热不足的佐证，不能单独定责。

建议文案方向：
- “检查锅炉温度、燃料料位和风机反馈。”
- “如果风温低但锅炉温度正常，优先检查风路、风机反馈或热交换效率。”
- “如果锅炉温度也低，优先检查燃料供应和锅炉运行状态。”

### 3.6 湿度偏高原因分析

输入：`MT1`、`MOISTURE.PREDICTED`、`FTT*`、`T_OUT2/T_OUT4`、`TT*`、`VF*`、`VFM*`、主机电流、下游滚筛/出料链路。

湿度偏高不是一个控制动作，而是一个根因排序问题。

| 候选原因 | 佐证 |
|---|---|
| 温度不足 | `FTT*` 或 `TT*` 相对基线偏低，且湿度上升 |
| 排湿不足 / 蒸汽滞留 | `T_OUT2/T_OUT4` 偏高，且风机反馈不足或湿度上升 |
| 风量不足 | `VF*` 反馈偏低，风温/出料温度/湿度同步异常 |
| 给料偏重 | `VFM*` 偏高，主机电流偏高，湿度上升 |
| 下游不畅 | `I_M11/I_M12/I_M13/I_M14` 高或滚筛/出料异常，湿度波动 |
| 传感器异常 | `MT1` 与 `MOISTURE.PREDICTED` 或工况趋势明显背离 |

建议文案方向：
- 先给根因排序，再给人工检查方向。
- 不输出“直接提高链速”。
- 若 softsensor 与 `MT1` 背离，建议复核湿度仪和离线化验，不强行按 `MT1` 控制。

## 4. 分级输出

v0.1 只做 L0-L2；L3 自动控制留到安全项关闭后。

| 等级 | 含义 | 系统动作 |
|---|---|---|
| L0 | 观察 | 记录趋势和 evidence，不提示操作员 |
| L1 | 提示 | 大屏 / operator-touch 展示“可能异常” |
| L2 | 人工确认建议 | 给出建议检查/调整方向，但不写 PLC |
| L3 | 自动控制 | 暂不启用；需 `P0-SAFETY`、`P0-CTRL-NAK`、`P0-CTRL-MODE` 全关闭 |

输出字段保持当前 edge-api 最小 schema：

## 5. v0.1 实现顺序

| 顺序 | 内容 | 验收 |
|---|---|---|
| 1 | 拓扑表 + 通用特征抽取 | 每条规则都能拿到当前值、30s、5m evidence |
| 2 | 堵料 / 空转 | 用输送电流 + 上下游料位/负载区分高负载和低负载 |
| 3 | 主机负载过高 | 主机电流与给料、风量、风温关联，发酵仓 保守输出 |
| 4 | 滚筛异常 | 覆盖 `M12/M13/M14` 出料链路 |
| 5 | 供热 / 风量异常 | 覆盖 `TT*`、`FTT*`、`VF*`、锅炉燃料线索 |
| 6 | 湿度偏高原因排序 | 融合 `MT1`、softsensor、温度、风量、给料、下游状态 |

每一步都要有单测覆盖：
- 数据缺失 / stale 时不强报。
- 只有单点异常时低置信度。
- 有上下游佐证时提升置信度。
- 输出始终 `actionable=false`，且包含 P0 阻断原因。
- 旧 `DRYER1.*` / `CHAIN.SPEED` 类输出不得回流。

## 6. 待现场标定

这些不是 v0.1 的前置，但会决定规则可靠性：

- 每台电机额定电流、空载电流、正常负载区间。
- `LL*` 料位信号极性、抖动特性、正常切换周期。
- `VFM*` / `VF*` 反馈单位、量程、与实际给料/风量的关系。
- `FTT*` / `TT*` 正常工况区间和报警上下限。
- `MT1` 与离线化验、`MOISTURE.PREDICTED` 的时延关系。
- PLC 报警码清单及报警码与 `M*` / `I_M*` / `FTT*` 的对应关系。

现场标定完成前，规则只做趋势诊断和人工建议，不做闭环控制。
