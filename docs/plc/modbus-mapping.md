# 🔌 Modbus 映射与 PLC 集成说明（Modbus Mapping & Integration）

> 版本：v1.0  
> 关联服务：`edge-daq`  
> 关联配置：`configs/tags.yaml`

---

## 1. 通信整体说明

- 协议：**Modbus TCP**  
- 通信模式：`edge-daq` 为 Modbus 客户端，PLC 为服务器  
- 功能码：
  - 读取保持寄存器（功能码 3）  
  - 写多个保持寄存器（功能码 16）——用于控制指令下发

---

## 2. 地址映射原则

- 将 PLC 寄存器地址抽象为 **逻辑 Tag**，通过 `configs/tags.yaml` 管理  
- 物理地址变动时，只需修改配置，无需改代码  
- 地址区间建议按功能划分：
  - 40001–40999：工艺过程值（温度、速度等）  
  - 41001–41999：设定值（Setpoint）  
  - 42001–42999：命令与状态  
  - 43001–43999：报警与故障码

## 4. `configs/tags.yaml` 中的配置字段

建议每个点位包含以下字段：

- `name`：逻辑 Tag 名（与 `tag-definition-standard.md` 对齐）  
- `address`：Modbus 寄存器地址（见下方“地址基准”说明）  
- `function_code`：读取功能码 `3/4`（默认 3）  
- `type`：`float` / `int` / `int32` / `uint32` / `bool` 等  
- `scale`：缩放系数（如 `0.1` 表示实际值=寄存器*0.1）  
- `unit`：物理单位  
- `description`：中文说明

### 4.1 地址基准（非常重要）

- Modbus 协议层地址通常是 **0 基址**（第一个保持寄存器地址是 0）。  
- 现场点表常写成 **40001/40010** 这类“人类编号”。  
- 为避免联调歧义，建议你们在点表/配置中明确：  
  - **方案 A（推荐）**：配置使用 0 基址（0/9/…），点表注明“0 基址”  
  - **方案 B**：配置使用 40001 形式，但 PLC/网关侧需按相同编号实现映射（并在点表显著标注）

### 4.2 32 位数值的字序/字节序

- 我们项目里 `byte_order: big/little` 目前用于控制 **32 位值的组字方向**。  
- 现场常见差异是 **word swap（高低 16 位寄存器交换）**，但每个 16 位寄存器内部仍是大端。  
- 建议联调时选一个 `float` 点（比如温度）做单点读写验证，确认实际组字规则后再批量填表。

## 5. edge-daq 集成流程

### 5.1 读取流程

1. 启动时读取 `configs/tags.yaml`，构建轮询列表  
2. 按点位类型和地址区间合并读请求，降低 Modbus 报文数量  
3. 对读取值应用缩放与类型转换  
4. 将结果封装为统一数据结构并发布到 MQTT

### 5.2 写入流程（控制下发）

1. 上层（`edge-api` / 大屏）将控制命令转成 Tag + Value  
2. `edge-daq` 接收 MQTT 控制消息  
3. 根据 Tag 查找对应 PLC 地址与缩放系数  
4. 使用功能码 16 写寄存器，实现对 PLC 的控制

## 7. 变更管理

- 任何 PLC 地址或类型变更必须：
  - 在 `tags.yaml` 中更新  
  - 更新本文档 / Excel 点位表  
  - 与算法/大屏团队同步，避免因 Tag 变化导致模型特征错误
