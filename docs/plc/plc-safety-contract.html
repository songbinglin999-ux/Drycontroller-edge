1. 总则

1.1 核心原则

edge 承担正常工艺控制、限幅、斜坡、工艺联锁与软件侧安全兜底；PLC 承担确定性执行、同步、仲裁和心跳丢失后的本地控制兜底；VFD/硬接线/设备自保护承担最终物理安全兜底。

  • Edge 系统（上位机）负责数据采集消费、分析、展示、工艺控制状态机、软点策略、range guard、setpoint ramp/slew limiter、工艺联锁、mode gate 和软件侧 fallback
  • PLC（可编程逻辑控制器）负责软点寄存器/执行接口、参数同步、报警同步、状态同步、执行、采集、ACK/NAK/原因码、无扰切换和 HMI/edge 控制权锁
  • PLC 读取 edge 心跳；edge 心跳丢失时，PLC 必须切回 PLC 本地控制，且切换过程不能造成突变输出
  • 现场触摸屏/HMI 属于 PLC 本地备用人工入口，必须具备 HMI->PLC 备用直连能力；edge 健康时 HMI 只监视或请求接管，edge 离线、网络断开、维护锁或 PLC_LOCAL/LOCAL_MANUAL 且 PLC 授权后，HMI 才能写允许的本地/手动控制软点
  • PLC 必须提供 AUTHORITY_OWNER、AUTHORITY_EPOCH、HMI_DIRECT_ENABLE、TAKEOVER_REASON 与 REJECT_CODE 等字段；edge 与 HMI 写控制软点时必须受当前 owner/epoch 约束
  • 硬件急停、热继、拉绳/跑偏等设备级保护仍属于现场硬件/PLC/VFD 执行层，edge 不直接驱动物理输出；这类硬安全不等同于 edge 的工艺联锁

侧状态

1.3 「安全状态」的定义

本契约多处提到「切到手动模式 / 安全 setpoint / 安全默认」。对干燥工艺，安全状态 不等于「所有输出立即归零」：骤停加热和风机可能导致余热堆积、物料闷烧。

  • 安全状态各执行器的具体目标值由 工艺部门 定义；工艺定义到位前，集成商不得默认用「全部输出归零」作为安全状态。
  • 本契约只约束「进入安全状态」这一安全动作，不规定产线启停流程（由产线工艺控制负责）。

1.4 本期控制范围与监测边界

本期我方（edge）的控制对象只有若干台变频电机；温度、电流等均为监测点，我方不直接控制。

类别对象我方角色说明
控制点若干台变频电机（上料 / 输送 / 滚筒 / 风机的频率与启停）下发设定值 + 启停请求（经 PLC 安全判断，不直接驱动 Y 输出）数量 N 与具体电机随点表冻结确定（TBD）
监测点工艺温度（锅炉）只读，上大屏 + 低温报警锅炉自带燃烧控制、自行控温，温度不是我方控制对象；我方仅监测 + 低温报警（运营告警 §1.5）。无超温问题，无自动停料——低温由人工判断处置
监测点上料电机电流只读，上大屏喂料 / 热量输入的间接指标，供人工调工艺参考；本期不报警

温度控制责任归属：工艺温度由锅炉本体系统负责控制（自控温）。本场景不涉及超温，无超温保护需求。我方侧对温度的全部动作仅为：监测上报、低温运营告警（提醒人看，§1.5）。低温后是否停料由人工判断，不做自动停料。

对锅炉系统的规格要求（写给锅炉厂，TBD 回填）：人工调工艺的前提是温度稳定，故锅炉需保证工艺温度稳定在 ___ ± ___ °C（数值待定）；低于下限触发低温报警。温度不稳导致工艺无法调整，责任在锅炉侧。

温度的自动控制 / 闭环调节（如「温度→上料快慢」回路）本期不做，列入后期（AI / 控制回写阶段，也可能不做）。

1.5 告警分级

告警按「是否动作、是否锁存」分两级，不可混为一谈（低温只是「提醒」，不是停机）：

层级例子动作锁存 / 复位执行方
硬安全联锁急停、电机热继、变频器故障、坏值 fail-safe停机进入安全状态锁存，人工复位PLC/VFD/硬接线（§2.6、§2.10）
运营告警工艺温度低温（提醒人看）仅提醒，不停任何设备；是否停料由人工决定自动消除，温度回正常即解除本地声光 + edge 大屏

低温报警「温度低 → 提醒人去看」既要本地声光报警（工人站在锅炉边能当场听见 / 看见，真正起作用）也要在大屏记录（曲线 + 历史，远端 / 复盘）；两者读同一温度值。无超温、无质量自动停料——低温后停不停料由工人现场判断。

2. PLC 侧安全要求（集成商必须实现）

2.1 门控心跳看门狗

寄存器EDGE_CONTROL_HEALTHY（地址待分配）
语义Edge 系统递增计数器，每秒 +1；仅当整条控制链路健康时才递增
PLC 行为心跳计数器在「看门狗超时窗口」内无变化 → 判定 edge 控制不可信 → 自动切手动模式
超时窗口看门狗超时 = 心跳周期 × 容忍丢拍数 + 余量，默认 1s × 3 + 1s ≈ 4s（唯一可调量是容忍丢拍数；不要再单独设一个独立的超时秒数与本式并存，见 §5）
判据看门狗监测「计数器值是否发生变化」（含溢出回绕 65535→0），不是「值是否递增」，否则回绕瞬间会误判超时
Fail-closedEdge 侧任一依赖异常（MQTT 断、API 挂、签名失败、range guard 失败）→ 心跳停止递增 → PLC 切手动

通俗说：PLC 每隔几秒看 edge 的心跳计数器有没有在变；如果在「超时窗口」内一直没变（连续丢够约定的拍数），就自己接管控制。

2.2 模式寄存器

寄存器CONTROL_MODE（地址待分配）
取值0 = 手动（现场手动控制），1 = 自动（edge 远程控制），2 = 维修锁（维修锁定，仅手动解除）
可读性Edge 系统可通过 Modbus 读取当前模式
切换条件见 §2.3 控制模式切换流程

2.3 控制模式切换流程

          门控心跳正常                门控心跳超时
┌──────────┐    ┌──────────┐    ┌──────────┐
│  自动模式  │ →  │  等待确认  │ →  │  手动模式  │
│ (MODE=1)  │    │  (防抖)    │    │ (MODE=0)  │
└──────────┘    └──────────┘    └──────────┘
      ↑                                │
      └────────── 心跳恢复 ────────────┘

         维修锁：人为置入 → 强制手动模式(MODE=2) → 仅手动解除可退出
         （锁定期间忽略 edge 心跳恢复，不自动接管）

关键规则：

  • 维修锁期间，edge 心跳恢复 不能 自动切回自动模式
  • 必须维修人员手动解除锁定后，才允许 edge 重新接管

2.4 本地安全 Setpoint

用途edge 挂了之后，PLC 自动切换到这组预设参数继续运行
内容各变频电机的链速、抽风频率等安全默认值（即 §1.3 定义的安全状态，由工艺部门确定；注意风机停机次序，不默认全部归零）。本期不含温度目标——温度由锅炉自控（§1.4）；安全 setpoint 存储在 PLC 本地、由现场人员设定，edge 只读不写
切换方式模式从 edge(1) 切到本地(0) 时，自动加载本地 setpoint
过渡要求bumpless 切换，输出不能跳变，平滑过渡

2.5 Actuator Final Clamp（最终输出限幅）

用途edge 已负责正常工艺限幅；PLC/VFD 只对已经到达执行层的输出做最终物理限幅兜底，防止异常命令或执行层配置错误伤害设备
示例频率指令 > VFD 上限 → VFD/PLC 强制压到上限；频率 < 允许下限 → 保持下限或 NAK（本期最终限幅对象为各变频电机的频率，不含温度——温度归锅炉，见 §1.4）
实现层级优先 VFD 参数，其次 PLC 程序内硬编码或安全功能块；不可被 edge 覆盖
告警触发 final clamp 时，置位告警标志位，edge 可读取并审计为执行层兜底

通俗说：正常情况下 edge 不应该发出越界目标；如果异常情况下真到了执行层，VFD/PLC 还要把“风机 80 Hz”压到物理安全范围。温度不是 edge 写入对象。

2.6 急停 / 硬安全联锁

急停硬件级紧急停止按钮，按下后所有输出归零或安全值，不经过任何软件
硬安全联锁安全联锁条件（如急停、门开、热继、变频器故障 → 对应输出安全化）。工艺温度不在此：温度归锅炉、本场景无超温、本期仅低温报警（人工处置），见 §1.4
工艺联锁上下游工况、数据新鲜度、模式/权限、给料/风机互斥等工艺联锁由 edge 控制状态机负责；不再要求 PLC 判断“为什么要调”
实现方式硬接线或安全 PLC 功能块，独立于 edge 系统
Edge 不介入硬安全急停/硬安全联锁的判断和执行在 PLC/VFD/硬接线侧，edge 不直接驱动物理输出；edge 只消费这些状态作为工艺决策证据

2.7 上电默认 / 断电恢复

触发覆盖三类：全线上电（冷启动）、PLC 单独复位/重启、动力回路单独断电恢复
行为任一触发后进入安全默认态：不自动带载、不沿用断电前的输出指令；先回读现场实际状态，判定完成前不驱动执行器
模式默认 CONTROL_MODE=手动，不自动交还 edge、不自动进入运行，需本地/人工显式启动
禁止不允许 PLC 记忆/延续断电前状态直接恢复（防一通电就按旧指令全速带载运转）
安全默认值各输出具体安全默认值由工艺确定（§1.3）；本契约只要求「不带载、不自动运行」，不规定启停流程
上电事件告警断电瞬间 PLC 发不出告警，须在上电初始化时回溯补报「发生过掉电/重启」（靠掉电保持/冷启动标志判别），走数据链路上报 cloud-ops；告警锁存至人工确认并重启，避免一闪而过被漏看。能区分冷启动/掉电恢复/暖复位则分类上报（取决于 PLC 型号，TBD）

全线启停、有序停机/重启流程不属本节，由产线工艺控制负责。

2.8 维修锁

触发方式维修工人在 PLC 侧手动操作（如拨动开关、HMI 按钮）
行为强制 PLC 进入手动模式(MODE=2)，忽略所有 edge 指令和心跳
解除方式仅手动解除，edge 无法远程解除
目的防止维修时 edge 恢复心跳后抢回控制权，导致设备突然动作伤人

2.9 DO 触点 → DTU 短信告警 暂缓

状态：暂缓（2026-06-04 决策）。依据：本产线有人值守，值守人员即作为 edge 失联时的发现与通知途径；本条维护成本（4G SIM 续费、DO 触点氧化、每周自检）在有人值守下性价比不足，暂不实施。
暂缓代价（集成商与甲方须共同知悉）：暂缓后全线告警均依赖 edge + 网络通路；一旦 edge 与网络同时中断，将没有独立于网络的告警兜底，只能靠现场值守人员当场发现处置。若产线改为无人 / 少人值守，必须先恢复本条。下方原方案保留备查。

用途独立于 edge、独立于网络的最后一道告警通道
触发条件门控心跳超时（edge 挂了）
实现方式PLC 的一个数字输出(DO) → 接 4G DTU → 发短信到运维手机
独立性即使 edge 全挂 + 网络全断，这条通道仍能工作
周期性自检这条平时不动的链路会静默失效（DO 触点氧化 / DTU 欠费 / SIM 失效）；需周期性自检（如每周自动触发一次测试短信），自检本身失败也要告警

2.10 传感器 / 反馈坏值 fail-safe

问题final clamp（§2.5）只限 输出指令，挡不住 输入坏值。本期我方不做加热 PID（温度归锅炉），但坏值仍会污染判断：①工艺温度探头断线/短路/超量程/长时间冻结 → 低温误报或漏报（§1.5）；②电机链速/反馈坏值 → edge 控制与工艺联锁误判
检测PLC 对关键反馈（温度、链速等 PV）做坏值检测：断线、超量程、长时间冻结不变
动作检测到坏值 → 该回路进入安全状态（见 §1.3），禁止拿坏值继续 PID 控制；置告警标志位，edge 可读
范围本节针对 PLC ↔ 现场仪表 这一段，独立于 edge↔PLC 链路安全

2.11 命令拒绝与原因码

edge 写入的是命令请求（启停、设定值、模式等），PLC 先做安全 / 状态判断再决定接受或拒绝，并通过 COMMAND_ACK（§4）+ REJECT_CODE 回告。拒绝码须随对应 COMMAND_ID 一起返回，让 edge 知道是哪条命令被拒、为何被拒。

码含义码含义
0无拒绝（ACK）8参数超上限
1急停中9参数低于下限
2本地 / 手动模式10当前状态不允许切换模式
3维修锁11启动反馈超时
4远程未授权12运行反馈异常
5设备故障13通讯 / 心跳超时
6联锁不满足14温度传感器异常 / 坏值
7下游未运行（顺序联锁）15变频器故障

码值为建议基线，最终以集成商 PLC 程序实现为准；新增拒绝原因时向后追加码值，不复用旧码语义。非法参数（超上下限 / 单位错）一律「拒绝写入 + 保持旧值」，不得部分写入。

2.12 控制权仲裁（edge / HMI / 本地）

多个写入源（edge 远程、现场 HMI、本地手动）不能同时写 PLC，否则冲突。PLC 持有控制权锁，任一时刻只授权一个写入源：

正常edge 健康（心跳正常）→ edge 持锁；现场 HMI 不争抢，只读显示
edge 失联心跳超时 → edge 失锁、PLC 进本地兜底；现场 HMI 仅在 PLC 显式授权后才可直连写入（备用人工入口）
维修维修锁（§2.8）置入 → 强制本地手动，忽略 edge 与 HMI 远程写
防双写任一时刻只有一个写入源被授权；切换走无扰流程（§2.3），输出不跳变
恢复edge 恢复后不自动夺锁，须读当前状态、同步、确认一致后再切回 edge 持锁

2.13 极简-PLC 降级方案（集成商能力不足时）

§2.1–§2.12 是目标版（「能干 PLC」）。若集成商无法完整实现，允许降级到下面的「极简-PLC」最小集——但安全底线一寸不让，只是把它从 PLC 程序挪到硬接线 / 变频器参数。

6. 失败注入验收

验收不能只覆盖正常路径，至少覆盖以下故障场景：

#场景预期行为
1Edge 系统关机（docker compose down）PLC 自动切手动模式，用安全 setpoint 继续运行
2Edge 进程崩溃（kill edge-daq）门控心跳停止，PLC 防抖后切手动
3心跳进程单独崩溃PLC 防抖后切手动；采集即使还在也不能保持自动模式
4MQTT 不可用门控心跳 fail-closed，PLC 切手动
5Edge API 不可用无新 command 下发，PLC 不依赖 edge-api 维持安全
6Modbus 写失败Command NAK，不重放危险写入，告警可见
7Edge 发越界指令Edge range guard 拒绝 → 不发到 PLC；万一到了执行层 → PLC/VFD final clamp 兜底
8维修锁期间 edge 恢复PLC 不自动接管，需手动解除锁定
9模式切换时输出跳变bumpless 过渡，输出平滑
10上电重启PLC 进入安全默认状态，不记忆上次状态
11硬件急停触发所有输出安全化，不经过任何软件
12边缘设备重启Tailscale/SSH/watchdog/compose 按序恢复，PLC 期间保持手动
13温度/反馈传感器坏值（断线/超量程/冻结）PLC 检测到坏值 → 该回路进入安全状态，不拿坏值继续 PID（§2.10）
14心跳计数器溢出回绕（65535→0）PLC 视为正常更新，不误判超时切手动（§2.1 判据）
15DO→DTU 告警链路自检周期性测试短信能收到；链路坏（DTU 欠费/SIM 失效）时自检失败并告警（§2.9）
16掉电后重新上电PLC 回溯补报锁存的掉电/上电告警，且产线不自动启动、停在本地安全模式待人工（§2.7）
17工艺温度低温触发低温报警（本地声光 + 大屏），不自动停任何设备，由人工判断处置（§1.5）
18命令被拒PLC 回 NAK + REJECT_CODE，随对应 COMMAND_ID；非法参数保持旧值不部分写入（§2.11）

9. 风险与免责

  1. V1 只允许六个频率目标 SP 在签收后启用；其他 edge 控制写入在 PLC 侧软点/同步/心跳/仲裁接口未签收前全部禁用。 这不是拖延，是安全保障。
