1. 总则

1.1 核心原则

PLC 是最后安全屏障，edge 不承担最终安全责任。

  • Edge 系统（上位机）负责数据采集、分析、展示和控制建议
  • PLC（可编程逻辑控制器）负责直接控制电机、阀门、加热器等硬件
  • 任何单点故障（edge 挂了、网络断了、软件 bug）都不应导致安全事故

1.2 当前状态

侧状态
PLC 侧全部未做，当前仅 Modbus passthrough（透传）
Edge 侧部分已做（心跳、range guard 代码框架），其余等 PLC 侧完成后跟进

1.3 「安全状态」的定义

本契约多处提到「切到手动模式 / 安全 setpoint / 安全默认」。对干燥工艺，安全状态 不等于「所有输出立即归零」：骤停加热和风机可能导致余热堆积、物料闷烧。

  • 安全状态各执行器的具体目标值由 工艺部门 定义；工艺定义到位前，集成商不得默认用「全部输出归零」作为安全状态。
  • 本契约只约束「进入安全状态」这一安全动作，不规定产线启停流程（由产线工艺控制负责）。

2. PLC 侧安全要求（集成商必须实现）

2.1 门控心跳看门狗

寄存器EDGE_CONTROL_HEALTHY（地址待分配）
语义Edge 系统递增计数器，每秒 +1；仅当整条控制链路健康时才递增
PLC 行为心跳计数器在「看门狗超时窗口」内无变化 → 判定 edge 控制不可信 → 自动切手动模式
超时窗口看门狗超时 = 心跳周期 × 容忍丢拍数 + 余量，默认 1s × 3 + 1s ≈ 4s（唯一可调量是容忍丢拍数；不要再单独设一个独立的超时秒数与本式并存，见 §5）
判据看门狗监测「计数器值是否发生变化」（含溢出回绕 65535→0），不是「值是否递增」，否则回绕瞬间会误判超时
Fail-closedEdge 侧任一依赖异常（MQTT 断、API 挂、签名失败、range guard 失败）→ 心跳停止递增 → PLC 切手动

通俗说：PLC 每隔几秒看 edge 的心跳计数器有没有在变；如果在「超时窗口」内一直没变（连续丢够约定的拍数），就自己接管控制。

2.2 模式寄存器

寄存器CONTROL_MODE（地址待分配）
取值0 = 手动（现场手动控制），1 = 自动（edge 远程控制），2 = 维修锁（维修锁定，仅手动解除）
可读性Edge 系统可通过 Modbus 读取当前模式
切换条件见 §2.3 控制模式切换流程

2.3 控制模式切换流程

          门控心跳正常                门控心跳超时
┌──────────┐    ┌──────────┐    ┌──────────┐
│  自动模式  │ →  │  等待确认  │ →  │  手动模式  │
│ (MODE=1)  │    │  (防抖)    │    │ (MODE=0)  │
└──────────┘    └──────────┘    └──────────┘
      ↑                                │
      └────────── 心跳恢复 ────────────┘

         维修锁：人为置入 → 强制手动模式(MODE=2) → 仅手动解除可退出
         （锁定期间忽略 edge 心跳恢复，不自动接管）

关键规则：

  • 维修锁期间，edge 心跳恢复 不能 自动切回自动模式
  • 必须维修人员手动解除锁定后，才允许 edge 重新接管

2.4 本地安全 Setpoint

用途edge 挂了之后，PLC 自动切换到这组预设参数继续运行
内容链速、抽风频率、温度目标等的安全默认值（即 §1.3 定义的安全状态，由工艺部门确定；注意加热/风机停机次序，不默认全部归零）
切换方式模式从 edge(1) 切到本地(0) 时，自动加载本地 setpoint
过渡要求bumpless 切换，输出不能跳变，平滑过渡

2.5 Actuator Clamp（输出限幅）

用途不管 edge 给什么指令，PLC 自动把输出限制在安全范围内
示例温度指令 > 120°C → 强制压到 120°C；链速 < 0.5 → 强制压到 0.5
实现层级PLC 程序内硬编码或安全功能块，不可被 edge 覆盖
告警触发 clamp 时，置位告警标志位，edge 可读取

通俗说：就算 edge 发了个“温度 500 度”的指令，PLC 也会自动压到安全范围。

2.6 急停 / 联锁

急停硬件级紧急停止按钮，按下后所有输出归零或安全值，不经过任何软件
联锁安全联锁条件（如门打开 → 自动停机、温度超限 → 自动断热）
实现方式硬接线或安全 PLC 功能块，独立于 edge 系统
Edge 不介入急停/联锁的判断和执行完全在 PLC 侧，edge 不参与

2.7 上电默认 / 断电恢复

触发覆盖三类：全线上电（冷启动）、PLC 单独复位/重启、动力回路单独断电恢复
行为任一触发后进入安全默认态：不自动带载、不沿用断电前的输出指令；先回读现场实际状态，判定完成前不驱动执行器
模式默认 CONTROL_MODE=手动，不自动交还 edge、不自动进入运行，需本地/人工显式启动
禁止不允许 PLC 记忆/延续断电前状态直接恢复（防一通电就按旧指令全速加热）
安全默认值各输出具体安全默认值由工艺确定（§1.3）；本契约只要求「不带载、不自动运行」，不规定启停流程
上电事件告警断电瞬间 PLC 发不出告警，须在上电初始化时回溯补报「发生过掉电/重启」（靠掉电保持/冷启动标志判别），走数据链路上报 cloud-ops；告警锁存至人工确认并重启，避免一闪而过被漏看。能区分冷启动/掉电恢复/暖复位则分类上报（取决于 PLC 型号，TBD）

全线启停、有序停机/重启流程不属本节，由产线工艺控制负责。

2.8 维修锁

触发方式维修工人在 PLC 侧手动操作（如拨动开关、HMI 按钮）
行为强制 PLC 进入手动模式(MODE=2)，忽略所有 edge 指令和心跳
解除方式仅手动解除，edge 无法远程解除
目的防止维修时 edge 恢复心跳后抢回控制权，导致设备突然动作伤人

2.9 DO 触点 → DTU 短信告警 暂缓

状态：暂缓（2026-06-04 决策）。依据：本产线有人值守，值守人员即作为 edge 失联时的发现与通知途径；本条维护成本（4G SIM 续费、DO 触点氧化、每周自检）在有人值守下性价比不足，暂不实施。
暂缓代价（集成商与甲方须共同知悉）：暂缓后全线告警均依赖 edge + 网络通路；一旦 edge 与网络同时中断，将没有独立于网络的告警兜底，只能靠现场值守人员当场发现处置。若产线改为无人 / 少人值守，必须先恢复本条。下方原方案保留备查。

用途独立于 edge、独立于网络的最后一道告警通道
触发条件门控心跳超时（edge 挂了）
实现方式PLC 的一个数字输出(DO) → 接 4G DTU → 发短信到运维手机
独立性即使 edge 全挂 + 网络全断，这条通道仍能工作
周期性自检这条平时不动的链路会静默失效（DO 触点氧化 / DTU 欠费 / SIM 失效）；需周期性自检（如每周自动触发一次测试短信），自检本身失败也要告警

2.10 传感器 / 反馈坏值 fail-safe

问题clamp（§2.5）只限 输出指令，挡不住 输入坏值 导致的失控。温度探头断线/短路/超量程读成坏值（如恒 0°C）时，PLC 本地 PID 会据此 全速加热 → 着火
检测PLC 对关键反馈（温度、链速等 PV）做坏值检测：断线、超量程、长时间冻结不变
动作检测到坏值 → 该回路进入安全状态（见 §1.3），禁止拿坏值继续 PID 控制；置告警标志位，edge 可读
范围本节针对 PLC ↔ 现场仪表 这一段，独立于 edge↔PLC 链路安全

4. 寄存器规划

待与集成商共同分配具体地址

寄存器名方向数据类型说明
EDGE_CONTROL_HEALTHYEdge → PLCUINT16 递增计数门控心跳，PLC 看门狗监测
HOST_ALIVEEdge → PLCUINT16 递增计数主机存活心跳，诊断用
CONTROL_MODEPLC → EdgeUINT8 (0/1/2)当前控制模式：手动/自动/维修锁
CLAMP_ACTIVEPLC → EdgeBOOLclamp 限幅触发标志
ESTOP_REQUESTEdge → PLCBOOL软件急停请求
COMMAND_ACKPLC → EdgeUINT8命令响应：0=待确认, 1=ACK, 2=NAK
COMMAND_IDEdge → PLCUINT32命令序列号，用于 ACK/NAK 关联
{TAG}_SPEdge → PLCREAL各控制参数设定值（链速、频率等）
{TAG}_PVPLC → EdgeREAL各控制参数实际值

数据格式：

  • REAL 类型：IEEE 754 浮点，32 位
  • 递增计数器：UINT16 溢出后归零重计（@1Hz 约 18 小时回绕一次）；PLC 看门狗以「值是否变化」为判据，回绕（65535→0）视为正常更新，不得当作超时或异常
  • 字节序：Big-Endian（与 Modbus 标准一致）

5. 时序要求

参数默认值说明
心跳周期1 秒Edge 每秒递增一次心跳计数器
容忍丢拍数3 拍允许偶发丢包的最大连续丢拍数（唯一可调量）
看门狗超时≈ 4 秒派生量：心跳周期 × 容忍丢拍数 + 1s 余量；PLC 在此窗口内计数器无变化即切手动。不要再单独定义一个独立的超时秒数与本式并存
模式切换防抖2 秒心跳恢复后等待 2 秒才允许切回自动模式
bumpless 过渡时间≤ 5 秒模式切换时输出平滑过渡的最大时间
命令响应超时5 秒Edge 发出命令后等待 ACK/NAK 的最大时间

以上参数为建议值，需与集成商根据现场工况确认。

看门狗超时的硬上界由工艺安全时间（PST）决定：edge 在异常 setpoint 下挂掉后、到物料/设备受损前的时间窗即 PST，看门狗超时必须 < PST。上面 ≈4 秒为占位，须工艺部门给出 PST 后复核（若 PST 很短，需同步缩短心跳周期）。

6. 失败注入验收

验收不能只覆盖正常路径，至少覆盖以下故障场景：

#场景预期行为
1Edge 系统关机（docker compose down）PLC 自动切手动模式，用安全 setpoint 继续运行
2Edge 进程崩溃（kill edge-daq）门控心跳停止，PLC 防抖后切手动
3心跳进程单独崩溃PLC 防抖后切手动；采集即使还在也不能保持自动模式
4MQTT 不可用门控心跳 fail-closed，PLC 切手动
5Edge API 不可用无新 command 下发，PLC 不依赖 edge-api 维持安全
6Modbus 写失败Command NAK，不重放危险写入，告警可见
7Edge 发越界指令Edge range guard 拒绝 → 不发到 PLC；万一到了 PLC → clamp 兜底
8维修锁期间 edge 恢复PLC 不自动接管，需手动解除锁定
9模式切换时输出跳变bumpless 过渡，输出平滑
10上电重启PLC 进入安全默认状态，不记忆上次状态
11硬件急停触发所有输出安全化，不经过任何软件
12边缘设备重启Tailscale/SSH/watchdog/compose 按序恢复，PLC 期间保持手动
13温度/反馈传感器坏值（断线/超量程/冻结）PLC 检测到坏值 → 该回路进入安全状态，不拿坏值继续 PID（§2.10）
14心跳计数器溢出回绕（65535→0）PLC 视为正常更新，不误判超时切手动（§2.1 判据）
15DO→DTU 告警链路自检周期性测试短信能收到；链路坏（DTU 欠费/SIM 失效）时自检失败并告警（§2.9）
16掉电后重新上电PLC 回溯补报锁存的掉电/上电告警，且产线不自动启动、停在本地安全模式待人工（§2.7）

9. 风险与免责

  1. PLC 侧未实现本契约要求前，edge 控制写入全部禁用。 这不是拖延，是安全保障。
  2. 本契约不覆盖 PLC 程序本身的 bug。 PLC 程序质量由集成商负责。
  3. 现场工艺参数（温度范围、链速范围等）由工艺部门确定。 本文档中的示例值仅为说明。
  4. 急停/联锁的硬件设计不在本契约范围内。 由设备制造商和安全部门负责。
