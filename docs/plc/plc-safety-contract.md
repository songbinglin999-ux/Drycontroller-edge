# PLC 安全契约（PLC Safety Contract）

**版本**：v1.0-draft  
**日期**：2026-06-03  
**状态**：待集成商签收  
**适用范围**：DryController 边缘控制系统与 PLC 侧安全责任划分  
**关联架构**：[Edge 架构 v2](../architecture/edge-architecture-v2.md)

---

## 1. 总则

### 1.1 核心原则

**PLC 是最后安全屏障，edge 不承担最终安全责任。**

- Edge 系统（上位机）负责数据采集、分析、展示和控制建议
- PLC（可编程逻辑控制器）负责直接控制电机、阀门、加热器等硬件
- 任何单点故障（edge 挂了、网络断了、软件 bug）都不应导致安全事故

### 1.2 当前状态

| 侧 | 状态 |
|---|---|
| PLC 侧 | **全部未做**，当前仅 Modbus passthrough（透传） |
| Edge 侧 | 部分已做（心跳、range guard 代码框架），其余等 PLC 侧完成后跟进 |

### 1.3 2026-07 交付范围

**PLC 采集 → 工程量换算/基础统计 → 阈值告警判断 → 大屏展示**

- 控制写入在本契约关闭前 **默认 disabled**
- AI 算法和控制回写整体延后

### 1.4 「安全状态」的定义

本契约多处提到「切到手动模式 / 安全 setpoint / 安全默认」。对干燥工艺，安全状态 **不等于「所有输出立即归零」**：骤停加热和风机可能导致余热堆积、物料闷烧。

- 安全状态各执行器的具体目标值由 **工艺部门** 定义；工艺定义到位前，集成商不得默认用「全部输出归零」作为安全状态。
- 本契约只约束「进入安全状态」这一安全动作，**不规定产线启停流程**（由产线工艺控制负责）。

## 2. PLC 侧安全要求（集成商必须实现）

### 2.1 门控心跳看门狗

| 项 | 要求 |
|---|---|
| 寄存器 | `EDGE_CONTROL_HEALTHY`（地址待分配） |
| 语义 | Edge 系统递增计数器，每秒 +1；仅当整条控制链路健康时才递增 |
| PLC 行为 | 心跳计数器在「看门狗超时窗口」内无变化 → 判定 edge 控制不可信 → 自动切手动模式 |
| 超时窗口 | `看门狗超时 = 心跳周期 × 容忍丢拍数 + 余量`，默认 `1s × 3 + 1s ≈ 4s`（唯一可调量是容忍丢拍数；**不要再单独设一个独立的超时秒数与本式并存**，见 §5） |
| 判据 | 看门狗监测「计数器值是否**发生变化**」（含溢出回绕 65535→0），**不是**「值是否递增」，否则回绕瞬间会误判超时 |
| Fail-closed | Edge 侧任一依赖异常（MQTT 断、API 挂、签名失败、range guard 失败）→ 心跳停止递增 → PLC 切手动 |

**通俗说**：PLC 每隔几秒看 edge 的心跳计数器有没有在变；如果在「超时窗口」内一直没变（连续丢够约定的拍数），就自己接管控制。

### 2.2 模式寄存器

| 项 | 要求 |
|---|---|
| 寄存器 | `CONTROL_MODE`（地址待分配） |
| 取值 | 0 = 手动模式，1 = 自动模式，2 = 维修锁 |
| 可读性 | Edge 系统可通过 Modbus 读取当前模式 |
| 切换条件 | 见 §2.3 控制模式切换流程 |

### 2.3 控制模式切换流程

```
          门控心跳正常                门控心跳超时
┌──────────┐    ┌──────────┐    ┌──────────┐
│ 自动模式 │ →  │ 等待确认  │ →  │ 手动模式  │
│ (MODE=1) │    │ (防抖)    │    │ (MODE=0) │
└──────────┘    └──────────┘    └──────────┘
      ↑                                │
      └────────── 心跳恢复 ────────────┘

         维修锁：人为置入 → 强制手动模式(MODE=2) → 仅手动解除可退出
         （锁定期间忽略 edge 心跳恢复，不自动接管）
```

**关键规则**：
- 维修锁期间，edge 心跳恢复 **不能** 自动切回 自动模式
- 必须维修人员手动解除锁定后，才允许 edge 重新接管

### 2.4 本地安全 Setpoint

| 项 | 要求 |
|---|---|
| 用途 | edge 挂了之后，PLC 自动切换到这组预设参数继续运行 |
| 内容 | 链速、抽风频率、温度目标等的安全默认值（即 §1.4 定义的安全状态，由工艺部门确定；注意加热/风机停机次序，不默认全部归零） |
| 切换方式 | 模式从 edge(1) 切到本地(0) 时，自动加载本地 setpoint |
| 过渡要求 | bumpless 切换，输出不能跳变，平滑过渡 |

### 2.5 Actuator Clamp（输出限幅）

| 项 | 要求 |
|---|---|
| 用途 | 不管 edge 给什么指令，PLC 自动把输出限制在安全范围内 |
| 示例 | 温度指令 > 120°C → 强制压到 120°C；链速 < 0.5 → 强制压到 0.5 |
| 实现层级 | PLC 程序内硬编码或安全功能块，不可被 edge 覆盖 |
| 告警 | 触发 clamp 时，置位告警标志位，edge 可读取 |

**通俗说**：就算 edge 发了个"温度 500 度"的指令，PLC 也会自动压到安全范围。

### 2.6 急停 / 联锁

| 项 | 要求 |
|---|---|
| 急停 | 硬件级紧急停止按钮，按下后所有输出归零或安全值，**不经过任何软件** |
| 联锁 | 安全联锁条件（如门打开 → 自动停机、温度超限 → 自动断热） |
| 实现方式 | 硬接线或安全 PLC 功能块，独立于 edge 系统 |
| Edge 不介入 | 急停/联锁的判断和执行完全在 PLC 侧，edge 不参与 |

### 2.7 上电默认 / 断电恢复

| 项 | 要求 |
|---|---|
| 触发 | 覆盖三类：全线上电（冷启动）、PLC 单独复位/重启、动力回路单独断电恢复 |
| 行为 | 任一触发后进入安全默认态：**不自动带载、不沿用断电前的输出指令**；先回读现场实际状态，判定完成前不驱动执行器 |
| 模式 | 默认 `CONTROL_MODE=手动`，不自动交还 edge、不自动进入运行，需本地/人工显式启动 |
| 禁止 | 不允许 PLC 记忆/延续断电前状态直接恢复（防一通电就按旧指令全速加热） |
| 安全默认值 | 各输出具体安全默认值由工艺确定（§1.4）；本契约只要求「不带载、不自动运行」，**不规定启停流程** |
| 上电事件告警 | 断电瞬间 PLC 发不出告警，须在**上电初始化时回溯补报**「发生过掉电/重启」（靠掉电保持/冷启动标志判别），走数据链路上报 cloud-ops；告警**锁存**至人工确认并重启，避免一闪而过被漏看。能区分冷启动/掉电恢复/暖复位则分类上报（取决于 PLC 型号，TBD） |

> 全线启停、有序停机/重启流程不属本节，由产线工艺控制负责。

### 2.8 维修锁

| 项 | 要求 |
|---|---|
| 触发方式 | 维修工人在 PLC 侧手动操作（如拨动开关、HMI 按钮） |
| 行为 | 强制 PLC 进入手动模式(MODE=2)，忽略所有 edge 指令和心跳 |
| 解除方式 | **仅手动解除**，edge 无法远程解除 |
| 目的 | 防止维修时 edge 恢复心跳后抢回控制权，导致设备突然动作伤人 |

### 2.9 DO 触点 → DTU 短信告警

| 项 | 要求 |
|---|---|
| 用途 | 独立于 edge、独立于网络的最后一道告警通道 |
| 触发条件 | 门控心跳超时（edge 挂了） |
| 实现方式 | PLC 的一个数字输出(DO) → 接 4G DTU → 发短信到运维手机 |
| 独立性 | 即使 edge 全挂 + 网络全断，这条通道仍能工作 |
| 周期性自检 | 这条平时不动的链路会静默失效（DO 触点氧化 / DTU 欠费 / SIM 失效）；需周期性自检（如每周自动触发一次测试短信），自检本身失败也要告警 |

### 2.10 传感器 / 反馈坏值 fail-safe

| 项 | 要求 |
|---|---|
| 问题 | clamp（§2.5）只限 **输出指令**，挡不住 **输入坏值** 导致的失控。温度探头断线/短路/超量程读成坏值（如恒 0°C）时，PLC 本地 PID 会据此 **全速加热 → 着火** |
| 检测 | PLC 对关键反馈（温度、链速等 PV）做坏值检测：断线、超量程、长时间冻结不变 |
| 动作 | 检测到坏值 → 该回路进入安全状态（见 §1.4），**禁止拿坏值继续 PID 控制**；置告警标志位，edge 可读 |
| 范围 | 本节针对 **PLC ↔ 现场仪表** 这一段，独立于 edge↔PLC 链路安全 |

## 3. Edge 侧安全要求（我方负责实现）

### 3.1 双心跳

| 心跳 | 语义 | 用途 |
|---|---|---|
| `HOST_ALIVE` | 主机或基础运行时还活着 | 仅用于诊断，PLC 不依赖它 |
| `EDGE_CONTROL_HEALTHY` | 整条控制链路健康 | PLC 看门狗监测这个，fail-closed |

**EDGE_CONTROL_HEALTHY 健康条件**（全部满足才递增）：
- MQTT 连接正常
- edge-api 可用
- 命令签名模块正常
- range guard 正常
- Modbus 写链路正常
- 最近一次写入/ACK 契约满足

**任一不满足 → 心跳停止递增 → PLC 切手动模式**

### 3.2 Range Guard（范围校验）

| 项 | 要求 |
|---|---|
| 位置 | edge-api 签发指令前 |
| 行为 | 检查参数是否在安全范围内，越界直接拒绝，写审计日志 |
| 变化率 | 除绝对边界外，还限制 **单步最大调整量 / 变化速率**（rate limit）；防止每条都在 range 内、却连续大步爬升（尤其 autopilot 下） |
| 配置 | 范围与速率定义在 `configs/limits.yaml`，与 PLC clamp 范围对齐 |
| 范围 SSOT | 安全限值同源：`limits.yaml` 与 PLC clamp 不得各自维护；约束关系 `edge range guard ⊆ PLC clamp ⊆ 物理安全极限`；任一侧变更须同步另一侧并重新验收 |
| 原则 | 不应依赖 PLC clamp 作为唯一防线，edge 侧先拦一次 |

### 3.3 模式状态机

| 项 | 要求 |
|---|---|
| 功能 | 管理 自动模式 ↔ 手动模式的切换 |
| 防抖 | 连续丢够「容忍丢拍数」（见 §5）才切手动，避免偶尔丢包误切 |
| 回读 | 定期读取 PLC 模式寄存器，确认实际模式与预期一致 |

### 3.4 `/control/estop`（软件急停接口）

| 项 | 要求 |
|---|---|
| 接口 | `POST /api/v1/control/estop` |
| 行为 | 远程触发后，通知 PLC 切手动模式，所有输出安全化 |
| 权限 | 仅授权运维人员可调用 |
| 注意 | 这是软件层面急停，硬件急停仍在 PLC 侧 |

### 3.5 Signed Command + ACK/NAK

| 项 | 要求 |
|---|---|
| 签名 | 每条控制指令由 edge-api 签发，带数字签名 |
| 时效 | command 带时间戳/有效期窗口，超期的陈旧命令一律拒绝（防网络抖动后积压的旧命令延迟批量执行）；与 `COMMAND_ID` 序列号互补 |
| 消费 | edge-daq 只接受签名指令，Modbus 写入 PLC |
| 响应 | PLC 执行后回复 ACK（成功）或 NAK（拒绝） |
| NAK 处理 | 拒绝不重放危险写入，记录审计日志，触发告警 |

### 3.6 Suggestion ≠ Command

| 项 | 要求 |
|---|---|
| AI 输出 | ai-ctrl-optimizer 只能输出 suggestion（建议），发布到独立 topic |
| 转换 | 由 edge-api 将 suggestion 转为 signed command |
| 禁止 | AI 永远不直接写 PLC，不旁路 edge-api 的 range guard / 签名 / 审计 |

### 3.7 授权层级

| 层级 | 行为 | 默认 |
|---|---|---|
| **manual** | 每条 suggestion 需人工确认，edge-api 才签发 command | ✅ 默认 |
| **autopilot** | edge-api 自动把 suggestion 转签名 command 下发 | ❌ 需人工授权 |

**autopilot 约束**：
- 需人工显式授权开启，默认不开
- **仅本契约关闭后允许启用**（依赖 PLC 兜底真实可用）
- 授权一直有效，直到运维手动退回 manual
- 进入手动模式 / 维修锁 / 任一依赖 fail-closed → 自动挂起回 manual
- 恢复后需重新人工授权才能再次进入 autopilot

## 4. 寄存器规划

> **待与集成商共同分配具体地址**

| 寄存器名 | 方向 | 数据类型 | 说明 |
|---|---|---|---|
| `EDGE_CONTROL_HEALTHY` | Edge → PLC | UINT16 递增计数 | 门控心跳，PLC 看门狗监测 |
| `HOST_ALIVE` | Edge → PLC | UINT16 递增计数 | 主机存活心跳，诊断用 |
| `CONTROL_MODE` | PLC → Edge | UINT8 (0/1/2) | 当前控制模式：手动/自动/维修锁 |
| `CLAMP_ACTIVE` | PLC → Edge | BOOL | clamp 限幅触发标志 |
| `ESTOP_REQUEST` | Edge → PLC | BOOL | 软件急停请求 |
| `COMMAND_ACK` | PLC → Edge | UINT8 | 命令响应：0=待确认, 1=ACK, 2=NAK |
| `COMMAND_ID` | Edge → PLC | UINT32 | 命令序列号，用于 ACK/NAK 关联 |
| `{TAG}_SP` | Edge → PLC | REAL | 各控制参数设定值（链速、频率等） |
| `{TAG}_PV` | PLC → Edge | REAL | 各控制参数实际值 |

**数据格式**：
- REAL 类型：IEEE 754 浮点，32 位
- 递增计数器：UINT16 溢出后归零重计（@1Hz 约 18 小时回绕一次）；PLC 看门狗以「值是否变化」为判据，回绕（65535→0）视为正常更新，不得当作超时或异常
- 字节序：Big-Endian（与 Modbus 标准一致）

## 5. 时序要求

| 参数 | 默认值 | 说明 |
|---|---|---|
| 心跳周期 | 1 秒 | Edge 每秒递增一次心跳计数器 |
| 容忍丢拍数 | 3 拍 | 允许偶发丢包的最大连续丢拍数（**唯一可调量**） |
| 看门狗超时 | ≈ 4 秒 | 派生量：`心跳周期 × 容忍丢拍数 + 1s 余量`；PLC 在此窗口内计数器无变化即切手动。不要再单独定义一个独立的超时秒数与本式并存 |
| 模式切换防抖 | 2 秒 | 心跳恢复后等待 2 秒才允许切回 自动模式 |
| bumpless 过渡时间 | ≤ 5 秒 | 模式切换时输出平滑过渡的最大时间 |
| 命令响应超时 | 5 秒 | Edge 发出命令后等待 ACK/NAK 的最大时间 |

> 以上参数为建议值，需与集成商根据现场工况确认。
>
> **看门狗超时的硬上界由工艺安全时间（PST）决定**：edge 在异常 setpoint 下挂掉后、到物料/设备受损前的时间窗即 PST，看门狗超时必须 **< PST**。上面 ≈4 秒为占位，须工艺部门给出 PST 后复核（若 PST 很短，需同步缩短心跳周期）。

## 6. 失败注入验收

验收不能只覆盖正常路径，至少覆盖以下故障场景：

| # | 场景 | 预期行为 |
|---|---|---|
| 1 | Edge 系统关机（`docker compose down`） | PLC 自动切手动模式，用安全 setpoint 继续运行 |
| 2 | Edge 进程崩溃（kill edge-daq） | 门控心跳停止，PLC 防抖后切手动 |
| 3 | 心跳进程单独崩溃 | PLC 防抖后切手动；采集即使还在也不能保持 自动模式 |
| 4 | MQTT 不可用 | 门控心跳 fail-closed，PLC 切手动 |
| 5 | Edge API 不可用 | 无新 command 下发，PLC 不依赖 edge-api 维持安全 |
| 6 | Modbus 写失败 | Command NAK，不重放危险写入，告警可见 |
| 7 | Edge 发越界指令 | Edge range guard 拒绝 → 不发到 PLC；万一到了 PLC → clamp 兜底 |
| 8 | 维修锁期间 edge 恢复 | PLC 不自动接管，需手动解除锁定 |
| 9 | 模式切换时输出跳变 | bumpless 过渡，输出平滑 |
| 10 | 上电重启 | PLC 进入安全默认状态，不记忆上次状态 |
| 11 | 硬件急停触发 | 所有输出安全化，不经过任何软件 |
| 12 | 边缘设备重启 | Tailscale/SSH/watchdog/compose 按序恢复，PLC 期间保持手动 |
| 13 | 温度/反馈传感器坏值（断线/超量程/冻结） | PLC 检测到坏值 → 该回路进入安全状态，不拿坏值继续 PID（§2.10） |
| 14 | 心跳计数器溢出回绕（65535→0） | PLC 视为正常更新，不误判超时切手动（§2.1 判据） |
| 15 | DO→DTU 告警链路自检 | 周期性测试短信能收到；链路坏（DTU 欠费/SIM 失效）时自检失败并告警（§2.9） |
| 16 | 掉电后重新上电 | PLC 回溯补报锁存的掉电/上电告警，且产线不自动启动、停在手动安全模式待人工（§2.7） |

## 7. 验收标准与关闭条件

### 7.1 PLC 侧验收清单

| # | 验收项 | 验收方式 | 状态 |
|---|---|---|---|
| P1 | 门控心跳看门狗 | Edge 停止心跳后，看门狗超时窗口内 PLC 自动切手动 | ❌ |
| P2 | 模式寄存器可读 | Edge Modbus 读取 CONTROL_MODE 正确 | ❌ |
| P3 | 手动安全 setpoint | 切手动后设备用安全参数继续运行 | ❌ |
| P4 | Actuator clamp | 越界指令被限幅到安全范围 | ❌ |
| P5 | 急停/联锁 | 硬件急停触发后输出安全化 | ❌ |
| P6 | 上电默认 | 上电后进入安全状态 | ❌ |
| P7 | 维修锁 | 锁定后 edge 无法接管，手动解除后可恢复 | ❌ |
| P8 | DO → DTU 短信 | 心跳超时后运维手机收到短信 | ❌ |
| P9 | 传感器坏值 fail-safe | 反馈坏值时该回路进入安全状态，不据坏值控制 | ❌ |

### 7.2 Edge 侧验收清单

| # | 验收项 | 验收方式 | 状态 |
