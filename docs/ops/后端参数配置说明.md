# 后端参数配置说明（中文）

本文档汇总 **Drycontroller 后端**涉及的所有参数配置，并用中文说明每个参数的用途、影响范围与调节建议。

参数来源分三类：
- **环境变量（env）**：主要由 `docker-compose.yml` 注入，或在代码中 `os.getenv(...)`/`Settings(BaseSettings)` 读取。
- **配置文件（yaml）**：挂载在 `/app/configs/` 下，主要包含 `tags.yaml / ai-config.yaml / monitor.yaml / qos.yaml / limits.yaml`。
- **运行时端点**：例如 `/health /ready /metrics`，用于编排/监控，不属于“参数”，但会在文中说明与哪些参数相关。

> 约定：文档里的“默认值”指代码中的默认；生产环境请显式配置 `.env`，避免隐式默认导致行为不确定。

---

## 一、docker-compose 需要提供的 `.env` 变量（全局）

这些变量在 `Drycontroller/docker-compose.yml` 中以 `${VAR}` 引用，通常必须在 `.env` 提供。

### 1. 数据库（Postgres）
- **POSTGRES_USER**：数据库用户名。影响：所有依赖 Postgres 的服务连接鉴权。
- **POSTGRES_PASSWORD**：数据库密码。影响同上（敏感信息）。
- **POSTGRES_DB**：数据库名。影响：初始化与连接目标库。
- **POSTGRES_HOST**：Postgres 主机名（容器内通常为 `postgres`/`edge-postgres` 或 `.env` 指定）。影响：`edge-api`、`license-service` 连接地址。
- **POSTGRES_PORT**：端口（默认 5432）。影响：同上。

### 2. 时序数据库（InfluxDB 2.x）
- **INFLUXDB_USERNAME**：Influx 初始化用户名（仅用于 Influx 容器初始化）。
- **INFLUXDB_PASSWORD**：Influx 初始化密码（仅用于 Influx 容器初始化）。
- **INFLUXDB_ORG**：组织名。影响：所有 Influx 客户端的组织参数。
- **INFLUXDB_BUCKET**：默认 Bucket。影响：数据写入/查询目标。
- **INFLUXDB_TOKEN**：管理/写入 token（敏感）。影响：所有服务写入/查询。
- **INFLUXDB_HOST**：Influx 主机。影响：各服务 Influx 连接地址。
- **INFLUXDB_PORT**：Influx 端口（默认 8086）。影响：同上。

### 3. 消息队列（MQTT / Mosquitto）
- **MQTT_BROKER**：MQTT Broker 地址（容器内通常为 `mosquitto`/`edge-mosquitto`）。
- **MQTT_PORT**：端口（默认 1883）。
- **MQTT_TLS**：是否启用 TLS（建议生产 `true`，端口一般为 8883）。
- **MQTT_USER_* / MQTT_PASSWORD_*（按服务拆分）**：账号口令（敏感）。建议至少拆分：
  - `MQTT_USER_EDGE_API` / `MQTT_PASSWORD_EDGE_API`
  - `MQTT_USER_EDGE_DAQ` / `MQTT_PASSWORD_EDGE_DAQ`
  - `MQTT_USER_AI_SOFTSENSOR` / `MQTT_PASSWORD_AI_SOFTSENSOR`
  - `MQTT_USER_EDGE_MONITOR` / `MQTT_PASSWORD_EDGE_MONITOR`

### 4. 控制闭环签名密钥（强烈建议生产必配）
- **CONTROL_SIGNATURE_SECRET**：控制指令 HMAC-SHA256 共享密钥（敏感）。  
  - **调节作用**：用于 `edge-api` 生成控制指令签名、`edge-daq` 校验签名，防伪造/篡改/重放。  
  - **风险**：不一致会导致控制全部拒绝；泄露会导致控制被伪造。  
  - **建议**：至少 32 字符随机串，定期轮换，严格权限管理。

### 5. 端口
- **EDGE_API_PORT**：宿主机暴露 `edge-api` 端口映射到容器 `8000`。
- **LICENSE_SERVICE_PORT**：宿主机暴露 `license-service` 端口映射到容器 `8000`。
- **EDGE_MONITOR_PORT**：宿主机暴露 `edge-monitor` 端口映射到容器 `8080`（compose 中默认 `8080`）。

### 6. PLC / 采集
- **PLC_HOST**：PLC IP/域名（默认 `192.168.1.100`，生产需按现场配置）。
- **PLC_PORT**：Modbus TCP 端口（默认 502）。
- **PLC_SLAVE_ID**：Modbus 从站 ID（默认 1）。
- **PLC_SCAN_INTERVAL**：采集扫描周期（秒）。  
  - **注意**：代码中还存在 `PLC_SCAN_INTERVAL` 的覆盖/兼容逻辑，最终以采集模块解释为准。

### 7. AI（模型路径）
- **AI_MODEL_PATH**：compose 里对 AI 服务的环境变量占位。  
  - **现状**：当前 `ai-softsensor` 实际从 `/app/configs/ai-config.yaml` 的 `model_path` 读取，`AI_MODEL_PATH` 更像预留/兼容变量。

### 8. 日志
- **LOG_LEVEL**：日志等级（常用 `DEBUG/INFO/WARNING/ERROR`）。  
  - **调节作用**：影响所有服务输出量与诊断信息；生产一般 `INFO`，排障短期开 `DEBUG`。

### 9. 工业级告警（Prometheus/Alertmanager）
项目支持以 Prometheus 采集 `/metrics` 并触发告警规则，再由 Alertmanager 聚合，最终由 `edge-monitor` 的 `/ops/alerts` 提供给运维前端展示。

- **ALERTMANAGER_BASE_URL**：Alertmanager 地址（示例：`http://alertmanager:9093`）。  
  - **现状**：已在 `docker-compose.yml` 为 `edge-monitor` 默认注入本地 Alertmanager。
  - **调节作用**：不配置时 `edge-monitor /ops/alerts` 返回 503（无法展示告警）。

## 二、全局通用环境变量（common/logging）

这些变量由 `Drycontroller/common/logging/bootstrap.py`、`events.py` 使用，影响所有服务的日志与事件写入。

### 1. 日志与实例标识
- **LOG_LEVEL**（默认 `INFO`）：同上。
- **LOG_ROOT**（默认 `/logs`）：日志根目录。  
  - **调节作用**：所有服务日志按 `LOG_ROOT/<service>/app.log` 落盘。
- **LOG_ROTATE_WHEN**（默认 `midnight`）：日志轮转周期（TimedRotatingFileHandler 的 `when`）。  
  - **调节作用**：控制按日/小时轮转等（例如 `H` 表示按小时）。
- **LOG_BACKUP_COUNT**（默认 `7`）：保留轮转文件数量。  
  - **调节作用**：防止磁盘被日志占满；生产建议结合磁盘容量与合规要求配置。
- **APP_ENV / ENVIRONMENT / ENV**（默认 `production`）：运行环境标识，用于日志字段 `env`。
- **INSTANCE_ID / HOSTNAME**：实例标识，用于日志字段 `instance`。

### 2. 关键事件写入 Influx（EventRecorder）
由 `Drycontroller/common/logging/events.py` 使用：
- **INFLUXDB_BUCKET / INFLUXDB_ORG / INFLUXDB_TOKEN**：缺失则事件记录器禁用。
- **INFLUXDB_HOST**（默认 `localhost`）
- **INFLUXDB_PORT**（默认 `8086`）
- **INFLUXDB_EVENT_MEASUREMENT**（默认 `service_events`）：事件写入 measurement 名称。  
  - **调节作用**：便于将“服务启动/异常/自愈”等事件集中到独立 measurement，方便告警与审计。

## 三、edge-api（服务：`services/edge-api`）

### A. Settings 配置（`app/core/config.py`，由环境变量覆盖）

#### 1) 应用基础
- **APP_NAME**（默认 `Edge Backend API`）：仅标识。
- **VERSION**（默认 `1.0.0`）：接口/日志展示。
- **DEBUG**（默认 `False`）：调试开关；为 True 时错误响应更详细且 uvicorn 可能 reload。
- **ENV**（默认 `production`）：环境标识。

#### 2) 日志
- **LOG_LEVEL**（默认 `INFO`）
- **LOG_DIR**（默认 `/logs/edge-api`）
- **LOG_FILE**（默认 `/logs/edge-api/app.log`）

#### 3) Postgres
- **POSTGRES_HOST/POSTGRES_PORT/POSTGRES_USER/POSTGRES_PASSWORD/POSTGRES_DB**：同上。  
  - **调节作用**：决定 API 的业务数据/授权数据存储位置。

#### 4) Influx
- **INFLUXDB_HOST/INFLUXDB_PORT/INFLUXDB_TOKEN/INFLUXDB_ORG/INFLUXDB_BUCKET**
- **TRAINING_MEASUREMENT**（默认 `softsensor_training_data`）：训练样本 measurement（用于查询软测量训练数据）。
- **SYSTEM_METRICS_MEASUREMENT**（默认 `system_metrics`）：系统指标 measurement（来自 `edge-monitor` 写入）。
- **SYSTEM_HEALTH_MEASUREMENT**（默认 `system_health`）：服务健康 measurement（来自 `edge-monitor` 写入）。

#### 5) MQTT
- **MQTT_BROKER/MQTT_PORT/MQTT_TLS**
- **MQTT_USER_* / MQTT_PASSWORD_*（按服务拆分）**
- **MQTT_CLIENT_ID**（默认 `edge-api`）：MQTT client id。

#### 6) API 安全
- **API_PREFIX**（默认 `/api/v1`）：路由前缀。
- **CORS_ORIGINS**（默认空列表）：允许跨域来源（支持 JSON 数组或逗号分隔）。  
  - **生产建议**：显式收敛到前端域名/IP，避免任意来源调用；未配置则默认不开放跨域。
- **CORS_ALLOW_CREDENTIALS**（默认 `False`）

#### 7) API Key 鉴权
- **API_KEY_HEADER**（默认 `X-API-Key`）：请求头名称。
- **CONTROL_API_KEYS**：控制权限 key 列表（逗号分隔也可）。
- **ADMIN_API_KEYS**：管理员权限 key 列表。
  - **调节作用**：为空时系统认为“未配置安全”，部分接口会返回 503 提示未启用。
- **READONLY_WS_ALLOWLIST**：只读 WebSocket 来源白名单（CIDR 或精确 host，逗号分隔也可）；用于 `/api/ws/realtime`、`/api/ws/ai`、`/api/ws/system`，默认放行 localhost、RFC1918 LAN 与 Tailscale `100.64.0.0/10`。

> 说明：edge-api 当前不启用 JWT/Session 登录体系，统一使用 API Key；未使用的 JWT/限流配置已移除，避免“配置存在但实际上不生效”的误导。

#### 10) 配置文件路径（容器内）
- **CONFIG_DIR**（默认 `/app/configs`）
- **TAGS_CONFIG**（默认 `/app/configs/tags.yaml`）
- **AI_CONFIG**（默认 `/app/configs/ai-config.yaml`）
- **QOS_CONFIG**（默认 `/app/configs/qos.yaml`）
- **LIMITS_CONFIG**（默认 `/app/configs/limits.yaml`）
- **MONITOR_CONFIG**（默认 `/app/configs/monitor.yaml`）
- **MONITOR_API_BASE**（默认 `http://edge-monitor:8080`）：`edge-api` 代理 `edge-monitor` 的基础地址（取日志/告警等）。

### B. MQTT 重连相关（`app/core/mqtt_client.py`）
- **MQTT_RECONNECT_MIN_DELAY**（默认 `1` 秒）：paho 自动重连的最小退避。
- **MQTT_RECONNECT_MAX_DELAY**（默认 `30` 秒）：paho 自动重连的最大退避。
- **MQTT_CONNECT_TIMEOUT_SEC**（默认 `5` 秒）：启动时等待首次连接的最长时间（超时会告警但不阻塞启动）。

### C. 控制命令主题/ACK（`app/services/control_command.py`）
- **MQTT_TOPIC_CONTROL_TPL**（默认 `control/{line}/tags`）：控制指令下发 topic 模板。
- **CONTROL_ACK_TOPIC_TPL**（默认 `control/{line}/acks`）：ACK topic 模板（edge-daq 回写执行结果）。
- **CONTROL_ACK_SUB_PATTERN**（默认 `control/+/acks`）：edge-api 订阅 ACK 的 pattern。
- **CONTROL_SIGNATURE_SECRET**（默认空，需要显式配置）：签名密钥（与 edge-daq 一致）。

### D. Influx measurement（`app/services/influx.py`）
- **INFLUXDB_MEASUREMENT**（默认 `industrial_data`）：工业采集数据的 measurement 名称（查询用）。

## 四、edge-daq（服务：`services/edge-daq`）

### A. 服务端口与运行模式（`daq/main.py`）
- **HEALTH_PORT**（默认 `8080`）：健康检查 HTTP 端口（提供 `/health /ready /metrics`）。
- **PLC_HOST**（默认 `192.168.1.100`）：PLC 地址。
- **PLC_PORT**（默认 `502`）：Modbus TCP 端口。
- **PLC_SLAVE_ID**（默认 `1`）：从站 ID。
- **PLC_CONNECT_TIMEOUT**（默认 `5` 秒）：连接超时。
- **USE_SIMULATOR**（默认 `false`）：是否使用模拟器替代真实 PLC（演示/测试用）。
- **PLC_HEARTBEAT_INTERVAL**（默认 `5` 秒）：心跳检测间隔（PLCReader 侧使用）。
- **PLC_HEARTBEAT_TIMEOUT_CYCLES**（默认 `3`）：连续超时次数阈值，达到后触发降级（停控制）。
- **PUBLISHER_DRAIN_TIMEOUT_SEC**（默认 `10` 秒）：停机时尽力冲刷缓冲/重放的超时时间。

### B. 采集扫描周期（`daq/plc_reader.py`）
- **PLC_SCAN_INTERVAL**：采集扫描周期（秒）。  
  - **调节作用**：越小实时性越高，但 PLC/网络/Influx 压力更大；生产需根据现场容量评估。

### C. Modbus 熔断/退避（`daq/modbus_client.py`）
- **MODBUS_CB_FAIL_THRESHOLD**（默认 `5`）：连续失败达到该值触发熔断（短时间不再尝试）。
- **MODBUS_CB_COOLDOWN**（默认 `5` 秒）：熔断冷却时间。
  - **调节建议**：PLC 抖动环境可适当增大 cooldown，避免频繁连接风暴；但过大可能增加恢复时间。

### D. 数据发布器 DataPublisher（`daq/publisher.py`）

#### 1) MQTT 连接与安全
- **MQTT_BROKER / MQTT_PORT / MQTT_TLS**
- **MQTT_USER / MQTT_PASSWORD**：容器内实际读取的用户名/密码（由 `docker-compose.yml` 从 `.env` 的 `MQTT_USER_EDGE_DAQ/MQTT_PASSWORD_EDGE_DAQ` 注入）。
- **MQTT_TLS**（默认 `false`）：是否启用 TLS。
- **MQTT_TLS_INSECURE**（默认 `false`）：是否允许不校验证书（不建议生产开启）。
- **MQTT_ALLOW_INSECURE**（默认 `false`）：是否允许在未启用 TLS 的情况下连接（生产建议关闭）。
- **MQTT_REQUIRE_AUTH**（默认 `true`）：是否要求用户名密码。
- **MQTT_BROKER_BACKUP**（默认空）：MQTT 备 broker（主不可用时切换）。
- **MQTT_PORT_BACKUP**（默认等于 MQTT_PORT）：备 broker 端口。
- **MQTT_TOPIC_REALTIME**（默认 `realtime/{LINE_ID}/tags`）：实时数据发布 topic。
- **MQTT_TOPIC_ALARM**（默认 `system/{LINE_ID}/alarms`）：报警 topic（若有报警发布逻辑）。

#### 2) Influx 连接与安全
- **INFLUXDB_HOST / INFLUXDB_PORT / INFLUXDB_ORG / INFLUXDB_BUCKET / INFLUXDB_TOKEN**
- **INFLUXDB_SCHEME**（默认 `http`）：`http/https`。
- **INFLUX_REQUIRE_AUTH**（默认 `true`）：是否必须 token。
- **INFLUXDB_HOST_BACKUP / INFLUXDB_PORT_BACKUP / INFLUXDB_SCHEME_BACKUP**：Influx 备链路配置。
- **INFLUXDB_TLS_CA / INFLUXDB_TLS_CERT / INFLUXDB_TLS_KEY**：Influx TLS 证书相关路径。
- **INFLUXDB_VERIFY_SSL**（默认 `true`）：是否校验证书。
- **INFLUXDB_MEASUREMENT**（默认 `industrial_data`）：写入的 measurement。

#### 3) 缓冲、落盘、死信（应对断网/断库，支撑 90 天游泳）
- **MQTT_BUFFER_MAX**（默认 `1000`）：MQTT 待发缓冲最大条数（内存 deque）。
- **INFLUX_BUFFER_MAX**（默认 `2000`）：Influx 待写缓冲最大条数。
- **BUFFER_DIR**（默认 `/data/edge-daq`）：缓冲落盘目录（jsonl）。
- **MQTT_BUFFER_PERSIST**（默认 `true`）：是否将 MQTT 缓冲落盘。
- **INFLUX_BUFFER_PERSIST**（默认 `true`）：是否将 Influx 缓冲落盘。
- **DEAD_LETTER_DIR**（默认 `${BUFFER_DIR}/deadletter`）：死信目录（写入失败/丢弃时落盘审计）。
- **BUFFER_FLUSH_INTERVAL**（默认 `5` 秒）：后台重放缓冲周期。

#### 4) Influx 批量、速率限制
- **INFLUX_BATCH_MAX**（默认 `500`）：单次批量写入最大点数。
- **INFLUX_FLUSH_INTERVAL**（默认 `2` 秒）：批量 flush 间隔。
- **INFLUX_MAX_POINTS_PER_SEC**（默认 `0` 表示不限制）：写入速率上限，避免 Influx 压垮。

#### 5) 时间戳质量
- **TS_MAX_SKEW_SEC**（默认 `300` 秒）：允许的时间偏移阈值（用于过滤异常时间戳，防止写入未来/过去过多导致查询异常）。

#### 6) 缓冲告警阈值
- **MQTT_BUFFER_WARN**（默认 `800`）：MQTT 缓冲超过该值计为告警（指标/日志）。
- **INFLUX_BUFFER_WARN**（默认 `1600`）：Influx 缓冲告警阈值。

#### 7) 幂等 ID 前缀
- **PUBLISH_ID_PREFIX**（默认 `LINE_ID`）：生成消息 id 的前缀（下游可用来去重）。

#### 8) 磁盘保护（防满盘）
- **BUFFER_MIN_FREE_BYTES**（默认 `0`）：落盘前要求的最小剩余空间（0 表示不检查）。  
  - **建议**：生产建议设置为 1~5GB（按磁盘容量调整），避免日志+缓冲写满盘。
- **DISABLE_PERSIST_ON_ENOSPC**（默认 `true`）：遇到磁盘满（ENOSPC）时自动禁用落盘，避免持续报错风暴。

#### 9) 背压（采集侧自适应放慢）
- **BACKPRESSURE_ENABLED**（默认 `true`）：是否启用背压建议。
- **BACKPRESSURE_MAX_DELAY_SEC**（默认 `1.0`）：缓冲接近满时建议采集循环额外延迟的上限。
- **BACKPRESSURE_RATIO_THRESHOLD**（默认 `0.9`）：缓冲占用比例超过该值开始施加背压。

### E. 控制订阅与写入 PLC（`daq/control.py`）
控制通道是“高风险路径”，参数影响安全性：
- **MQTT_TOPIC_CONTROL**（默认 `control/{line}/tags`）：订阅控制指令 topic。
- **CONTROL_MIN_INTERVAL_MS**（默认 `500` ms）：同一 tag 的最小下发间隔（防抖/保护 PLC）。
- **MQTT_TLS**（默认 `false`） + **MQTT_ALLOW_INSECURE**：控制通道默认要求 TLS，除非显式允许不安全连接。
- **CONTROL_ALLOW_ANONYMOUS**（默认 `false`）：未提供 MQTT 用户密码时是否允许匿名控制（生产建议 `false`）。
- **CONTROL_ALLOWED_TAGS**（默认空）：控制白名单（逗号分隔）。  
  - **调节作用**：进一步限制哪些 tag 允许控制下发（即使 tags.yaml 里写了 `control_enabled`）。
- **CONTROL_ACK_TOPIC**（默认 `control/{line}/acks`）：写入 PLC 后回写 ACK 主题。
- **CONTROL_IDEMPOTENCY_WINDOW_SEC**（默认 `30` 秒）：时间窗（防重放/过期指令丢弃）。
- **CONTROL_REQUIRE_TIMESTAMP**（默认 `true`）：是否要求指令携带时间戳 `ts`。
- **CONTROL_REQUIRE_ID**（默认 `true`）：是否要求指令携带 `id`。
- **CONTROL_REQUIRE_SIGNATURE**（默认 `true`）：是否要求指令携带签名 `sig`。
- **CONTROL_SIGNATURE_SECRET**（默认空，生产必配）：HMAC 签名密钥。
- **CONTROL_ID_CACHE_SIZE**（默认 `1000`）：已处理 `id` 缓存大小（防重放）。

### F. 模拟器（`simulator.py`）
- **SIMULATOR_INTERVAL**（默认 `1.0` 秒）：模拟数据生成周期。

## 五、ai-softsensor（服务：`services/ai-softsensor`）

### A. 健康检查端口（`src/main.py`）
- **HEALTH_PORT**（默认 `8080`）：健康检查端口，提供 `/health /ready /metrics`。  
  - `/ready` 会检查 **服务 running + 模型已加载 + MQTT 已连接**，不满足返回 503（便于编排正确判定不可用）。

### B. MQTT & Influx（`src/mqtt_handler.py`）
- **MQTT_BROKER / MQTT_PORT / MQTT_TLS**
- **MQTT_USER / MQTT_PASSWORD**：容器内读取（由 `docker-compose.yml` 从 `.env` 的 `MQTT_USER_AI_SOFTSENSOR/MQTT_PASSWORD_AI_SOFTSENSOR` 注入）。
- **LINE_ID**（默认 `L1`）：产线标识，用于 topic 渲染与 payload 中的 `line` 字段。
- **MQTT_TOPIC_REALTIME**（默认 `realtime/{LINE_ID}/tags`）：订阅实时数据 topic。
- **INFLUXDB_HOST / INFLUXDB_PORT / INFLUXDB_TOKEN / INFLUXDB_ORG / INFLUXDB_BUCKET**
- **INFLUXDB_MEASUREMENT**（默认 `industrial_data`）：预测结果写入的 measurement（与 realtime 同表时可用于统一查询）。
- **INFLUXDB_TRAIN_MEASUREMENT**（默认 `softsensor_training_data`）：训练样本 measurement（会写入输入特征 + 预测输出 + 推理耗时等）。

### C. 数据质量监控与长期运行保护（`src/mqtt_handler.py`）

以下参数用于 **90 天游泳**场景：避免“数据异常导致误判”、避免“断链后必须人工介入”。

#### 1) 数据新鲜度 / 冻结检测 / 推理节流
- **SOFTSENSOR_MAX_FEATURE_AGE_SEC**（默认 `10` 秒）：参与推理的输入特征允许的最大“数据年龄”。  
  - **调节作用**：超过该年龄的特征会导致本次推理跳过，并在 `/metrics` 中累计 `softsensor_feature_stale_total`。  
  - **建议**：一般设置为采集周期的 5～10 倍；太小会导致频繁跳过推理，太大可能用到过期数据。
- **SOFTSENSOR_FREEZE_SEC**（默认 `120` 秒）：特征值长时间不变化时判定“可能冻结/链路卡住”。  
  - **调节作用**：冻结会累计 `softsensor_feature_frozen_total`；冻结特征过多会跳过推理（避免输出误导）。
- **SOFTSENSOR_MAX_FROZEN_FEATURES**（默认 `2`）：允许“冻结”的特征数量上限。  
  - **调节作用**：超过该数量则跳过推理；用于过滤“多数特征都不变”的异常场景。
- **SOFTSENSOR_INFERENCE_MIN_INTERVAL_SEC**（默认 `1.0` 秒）：最小推理间隔（节流）。  
  - **调节作用**：避免 tag 高频更新导致推理风暴；会累计 `softsensor_inference_skipped_throttle_total`。

#### 1.1) readiness 数据质量门控（用于告警/运维展示链路）
`edge-monitor` 默认会探活 `ai-softsensor` 的 `/ready`。以下参数决定什么情况下 `/ready` 返回 503（表示“软测量不可信/不可用”）：
- **SOFTSENSOR_READY_REQUIRE_RECENT_INFERENCE**（默认 `true`）：是否要求“最近必须推理成功过”。  
  - **true**：服务启动后若一直没有完成推理（例如特征缺失/断链），会一直 not-ready（更适合无人值守告警）。  
  - **false**：只要 MQTT 连通+模型加载就认为 ready（更宽松）。
- **SOFTSENSOR_READY_MAX_INFERENCE_AGE_SEC**（默认 `60` 秒）：最近一次推理成功距离现在的最大允许时间。  
  - **调节作用**：超过该值则 `/ready`=503，通常用来告警“推理停摆/长时间无输出”。
- **SOFTSENSOR_READY_MAX_FEATURE_AGE_SEC**（默认等于 `SOFTSENSOR_MAX_FEATURE_AGE_SEC`）：允许用于推理的输入特征最大 age。  
  - **调节作用**：当特征过期（数据不新鲜）时，/ready 置为 503 触发告警链路。
- **SOFTSENSOR_READY_MAX_FROZEN_FEATURES**（默认 `2`）：冻结特征数量阈值，超过则 `/ready`=503。  
  - **调节作用**：用于告警“传感器/链路可能冻结导致软测量失真”。

#### 2) MQTT 推理结果 outbox（断链不丢）
- **SOFTSENSOR_MQTT_OUTBOX_ENABLED**（默认 `true`）：MQTT 断链时是否缓存推理结果，待恢复后重放。
- **SOFTSENSOR_MQTT_OUTBOX_MAX**（默认 `500`）：outbox 最大缓存条数（超过会丢弃并计数 `softsensor_ai_outbox_dropped_total`）。

#### 3) Influx 写入缓冲与重放（断库自愈）
- **SOFTSENSOR_INFLUX_BUFFER_ENABLED**（默认 `true`）：Influx 写入失败时是否缓存点位，待恢复后重放。
- **SOFTSENSOR_INFLUX_BUFFER_MAX**（默认 `2000`）：Influx 缓冲最大点数（超过会丢弃并计数 `softsensor_influx_buffer_dropped_total`）。
- **SOFTSENSOR_FLUSH_INTERVAL_SEC**（默认 `2` 秒）：后台 flush 周期（重放 outbox 与 Influx 缓冲）。
- **SOFTSENSOR_INFLUX_RECONNECT_MAX_SEC**（默认 `30` 秒）：Influx 重连最大退避秒数（指数退避上限）。

#### 4) Prometheus 指标（`/metrics`）
关键指标名称（用于告警/看板）：
- **softsensor_mqtt_rx_total / softsensor_mqtt_rx_parse_error_total / softsensor_mqtt_rx_invalid_value_total**：输入消息接收/解析失败/无效值统计
- **softsensor_feature_missing_total{feature} / softsensor_feature_stale_total{feature} / softsensor_feature_frozen_total{feature}**：缺失/过期/冻结特征
- **softsensor_inference_scheduled_total / softsensor_inference_skipped_throttle_total / softsensor_inference_failed_total**：推理调度/节流/失败统计
- **softsensor_inference_duration_ms / softsensor_inference_last_ts / softsensor_feature_max_age_sec**：推理耗时/最近推理时间/特征最大 age
- **softsensor_ai_outbox_size / softsensor_ai_publish_failure_total / softsensor_ai_outbox_dropped_total**：推理结果 MQTT 重放队列状态
- **softsensor_influx_connected / softsensor_influx_buffer_size / softsensor_influx_write_failure_total / softsensor_influx_buffer_dropped_total**：Influx 通路与缓冲状态

> 说明：模型本身的路径/特征等主要来自 `configs/ai-config.yaml`，见下文。

## 七、license-service（服务：`services/license-service`）

### docker-compose 注入
- **LICENSE_CHECK_ENABLED**：是否启用授权校验。生产默认应启用；仅开发或故障旁路时才设置为 `false`。
- **LICENSE_FILE_PATH**（默认 `/etc/drycontroller/license/license.json`）：云端激活后落盘的本地签名 license。
- **LICENSE_PUBLIC_KEY_PATH**（默认 `/etc/drycontroller/keys/license.pub`）：license 验签公钥。
- **LICENSE_MACHINE_ID**：可选，显式指定本机 machine id；为空时服务读取 `/etc/machine-id`。
- **LICENSE_EXPIRY_DAYS**：兼容保留；license 有效期以签名 license 内的 `expires_at` 为准。
- **POSTGRES_***：数据库连接信息。
- **INFLUXDB_***：事件/指标上报（若后续实现）。
- **LOG_LEVEL**

`/verify` 会读取本地 license 与公钥，校验签名、有效期和 machine id，返回 `valid/reason/license`。失败 reason 包括 `missing_license_file`、`missing_public_key`、`signature_invalid`、`malformed_license`、`not_yet_valid`、`expired`、`machine_mismatch`。

## 九、configs 配置文件字段说明（/app/configs 挂载）

### 1) `configs/tags.yaml`（PLC 标签/采集配置）

#### naming（命名规范）
- **naming.format / naming.separator**：标签命名模板与分隔符（用于规范化，不直接影响采集逻辑）。
- **naming.notes/equipment/section_alias/examples**：文档性字段，用于统一标准。

#### tags（点位定义）
每个 tag 常见字段：
- **name**：标签名（例如 `DRYER1.OUT.TEMP`）。用于 MQTT/Influx/前端展示。
- **address**：Modbus 寄存器地址（与 `docs/plc/modbus-mapping.md` 对齐）。
- **type**：数据类型（如 `float/int/int32/uint32/bool`），决定解码/写入方式。
- **unit**：单位（用于展示）。
- **description**：中文说明（用于 UI/运维）。
- **range**：合理范围（用于报警/控制校验）。
- **alarm_high/alarm_low**：报警阈值（若报警模块使用）。
- **control_enabled**：是否允许控制写入（控制链路必须为 true 才能下发）。
- **byte_order/scale/function_code**：部分 tag 支持（在 edge-daq 控制/读取中会校验/使用）。

#### mqtt（发布配置）
- **mqtt.base_topic**：基础 topic（例如 `realtime`）。
- **mqtt.publish_interval**：发布周期（秒）。  
  - **注意**：当前发布周期也可能受 `PLC_SCAN_INTERVAL` 等影响，需保持一致。
- **mqtt.qos**：QoS（0/1/2）。
- **mqtt.retain**：retain（是否让 broker 保留最新值）。

#### acquisition（采集配置）
- **acquisition.scan_interval**：扫描周期（秒）。
- **acquisition.batch_size**：批处理大小（影响吞吐与延迟）。
- **acquisition.timeout**：采集超时（秒）。

### 2) `configs/ai-config.yaml`（AI 模型/推理/优化配置）

#### softsensor
- **model_name/model_version/model_path**：模型标识与路径（容器内一般在 `/app/models`）。
- **input_features**：推理输入特征（必须与 realtime 标签一致；缺失会导致无法推理/等待特征齐全）。
- **output.name/unit/range/target**：输出标签与单位/范围/目标值（目标值用于置信度估计等）。
- **preprocessing.method/scaler_path**：预处理与 scaler 路径（当前模型加载为占位，后续 ONNX/Scaler 集成会用到）。
- **inference.batch_size/timeout/min_confidence**：推理参数（超时、最低置信度等，部分需结合代码是否生效）。
- **publish.mqtt_topic/interval**：发布 topic 模板与发布间隔（当前 `ai-softsensor` 主要在特征齐备时推理并发布）。

#### optimizer（控制优化）
该部分用于未来优化器实现：
- **objectives**：优化目标（含权重/最小化等）。
- **control_variables**：可调控制变量范围与步长。
- **constraints**：工艺约束（温度/扭矩/链速关系等）。
- **optimization**：算法配置（pso/genetic/gradient 等）。
- **execution.mode/interval/confidence_threshold**：执行模式与周期（advisory/auto）。
- **publish.mqtt_topic**：发布 topic（例如 `ai/{line}/control`）。

#### training / metrics
训练与评估指标定义，当前更多用于文档与未来训练流水线对齐。

### 3) `configs/monitor.yaml`（监控与自愈策略）
- **line_id**：产线标识（默认 L1）。
- **system.interval**：系统指标采集间隔（秒）。
- **system.disk_path**：磁盘路径（用于 disk usage）。
- **system.publish_mqtt**：是否发布状态到 MQTT。
- **services.interval**：服务健康检查间隔（秒）。
- **services.http_timeout**：HTTP 探活超时（秒）。
- **services.failure_threshold**：连续失败阈值（触发自愈的默认值）。
- **services.recovery_observe**：重启后观察周期数（用于 cooldown）。
- **services.max_restart_per_hour**：每小时最大自愈重启次数。
- **services.self_heal.enabled**：全局自愈开关。
- **services.targets[]**：监控目标列表（name/url/container/tcp/self_heal 覆盖等）。
  - **url**：建议用 `/ready`（能反映依赖链路），而不仅仅 `/health`。

### 4) `configs/qos.yaml`（QoS/限流/数据保留“策略文件”）
> 说明：该文件目前更多作为“统一策略定义”，是否完全在代码里生效需要逐服务对齐实现。

核心字段：
- **data_acquisition**：采集 QoS（scan_rate/max_latency/buffer/drop_policy/retry）。
- **mqtt**：不同 topic 的 QoS 与连接参数（keepalive/clean_session/reconnect_delay_max）。
- **rate_limiting**：API 限流策略（按 IP/按 endpoint）。
- **database**：连接池/写入批次/重试策略。
- **cache**：缓存开关、后端与 TTL 策略。
- **data_retention**：Influx/Postgres 数据保留建议（需要配合数据库侧策略落地）。
- **performance**：性能阈值建议（用于告警/看板）。

### 5) `configs/limits.yaml`（工艺限制/报警/联锁“策略文件”）
> 说明：该文件主要用于工艺安全边界定义，是否在代码中自动触发联锁需要结合控制策略实现。

核心字段：
- **temperature_limits/speed_limits/torque_limits/fan_limits/moisture_limits/humidity_limits**：各类工艺边界与推荐区间。
- **alarms.priorities**：报警级别定义（颜色/动作/是否自动清除/是否需要确认等）。
- **alarms.rules**：报警规则模板（条件/冷却等）。
- **interlocks**：安全联锁（触发条件与动作）。
- **control_constraints**：控制变化率/同时变更限制。
- **recommended_parameters**：推荐工况参数（可作为 UI 默认或优化建议参考）。

## 十、建议：生产落地时“必须显式配置”的关键项（避免 90 天游泳中断）

- **控制安全**：`CONTROL_SIGNATURE_SECRET`（必须一致且强随机）
- **MQTT 安全**：账号按服务拆分（`MQTT_USER_* / MQTT_PASSWORD_*`）+ 生产建议 `MQTT_TLS=true`（并配置 broker TLS/ACL）
- **Influx 认证**：`INFLUXDB_TOKEN/INFLUXDB_ORG/INFLUXDB_BUCKET`
- **磁盘保护**：`LOG_BACKUP_COUNT`、`BUFFER_MIN_FREE_BYTES`、Influx retention（见 `qos.yaml` 的 data_retention）
- **就绪探针**：监控目标尽量用 `/ready`（`monitor.yaml` 里可调整）

## 十一、哪些参数是“预留/未完全生效”

为了避免误解，这里明确标注：
- `configs/qos.yaml`、`configs/limits.yaml` 中不少字段当前属于“策略定义”，**需要业务代码显式读取并执行**才会真正影响行为。
- `LICENSE_EXPIRY_DAYS` 在 edge 侧仅兼容保留；实际授权有效期由云端签发的 license `expires_at` 决定。
- `AI_MODEL_PATH` 在 compose 中存在，但软测量/优化器当前主要按 `ai-config.yaml` 的 `model_path` 运行（变量更多是预留/兼容）。
